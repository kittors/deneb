## 主会话的决定（11-08）

1. **Web 全用 TypeScript**。理由：MyGo 在浏览器里读屏读不到、手机上手指不能滚也不能放大，M3 里都解决不了；手机打开邀请链接是常见场景。条件是用户那句"web端的风格也得和我们的桌面端的风格一致"：
   - 设计变量（颜色、圆角、阴影、字号、动效时长、设备块和小球的样式）从桌面端抽成一份 `web/tokens.json`，Web 只从这份读；最好由桌面端的代码自动生成，改一处两边都变。
   - 画布、设备块、连线和流动的光，用 Canvas 2D 或 SVG 在 TS 里照桌面端的画法重写。
   - 出设计时，Web 和桌面的截图并排给用户看。
2. **中转站在管理端分三种人看**：
   - **局域网拥有者看公共中转站**：只能看：地区、在不在线、延迟、每条连接限速多少，加一句"自动兜底，不用管"；别人用了多少看不到。
   - **自己的中转站**：全都能管：一行命令装上、拖进局域网、看负载、调权重、设权限、踢人。
   - **部署的人**（我们自己运营，或者别人自己部署）：单独的"运营"页，只有部署管理员看得到。公共中转站在那里管：加中转站用同一种一行命令；看负载（几台设备、几个人、带宽、流量）、调权重、踢人。服务器要加部署管理员的身份和对应的接口，第 3 步前和控制线对。

## 1. MyGo 在浏览器里的实测（11-08）

### 结论

| 项 | §2.5 的线 | 实测 | 达标 |
| --- | --- | --- | --- |
| 体积 | ≤ 15 MB | Web 版估 14.6 MB（brotli 后 2.9 MB）；把 `proto` 里的证书校验拆出去能降到约 13.2 MB | 贴着线 |
| 首屏，第一次打开 | ≤ 3 秒 | 几乎全是下载时间。20M 宽带约 1.5 秒；10M 约 2.8 秒；手机慢 4G 约 15 秒；10M 加上慢 4 倍的 CPU 约 3.5 秒 | 宽带达标，手机网络不达标 |
| 首屏，再次打开 | | wasm 按内容命名，可以一直缓存：0.4–1.2 秒 | 达标 |
| 中文输入法 | | Chrome 里拼音组合时画面上有带下划线的预编辑字，提交正确；隐藏的输入框跟着光标走，候选框会出现在光标旁边 | 达标（Safari、真输入法没测） |
| 读屏 | | 整页的无障碍树只有一个 canvas 和一个没名字的输入框，画面上的字和按钮一个都读不到。MyGo 文档写明浏览器里还不支持 | **不达标**，M3 内没法解决 |
| 手机 | | canvas 设了 `touch-action: none`：手指拖动不能滚动（实测，滚轮能滚），也不能双指放大 | **不达标** |

另外：浏览器的页内查找、翻译、选中复制文字、链接右键都用不了，因为字画在 canvas 里。桌面布局在 390 宽的手机上会挤坏，但这一点换哪种做法都要重新设计。

### 量了什么

三份样本，编译参数都和 `mygo build -platform web` 一样（`-trimpath -ldflags "-s -w -X …production=1" -tags mygo_noinspector`）：

| 样本 | wasm | gzip | brotli |
| --- | --- | --- | --- |
| MyGo 自带的 counter | 11.47 MB | 3.12 MB | 2.27 MB |
| 最小 Web 版（`web/probe/size`：MyGo 界面、`proto` 的用户视图、浏览器的 fetch） | 13.10 MB | 3.53 MB | 2.60 MB |
| 整个桌面客户端，演示模式（`cmd/deneb`；用 build overlay 换掉引擎本机接口里 js 编不过的一行，仓库不改） | 21.73 MB | 5.45 MB | 3.96 MB |

- **体积怎么估的**：按 wasm 名字段统计每个包的代码量。最小 Web 版比 counter 多 1.0 MB，几乎全是 `proto/keys.go` 引进来的 `crypto/tls`、`crypto/x509`（证书校验，Web 用不上）。桌面客户端比最小 Web 版多 5.3 MB，其中界面代码 0.84 MB，其余是 `net/http`、TLS、本机引擎客户端，Web 都不要。Web 版 ≈ 最小 Web 版 + 一份和桌面差不多大的界面代码（连带数据约 1.5 MB）≈ 14.6 MB。
- **首屏**：独立的无头 Chrome（临时配置目录），空缓存，CDP 限速，服务器按 brotli 发 wasm，钩住 WebGL 的第一次绘制，算"从打开链接到第一帧上屏"。每种条件 3 次取中位数，单位秒：

  | 条件 | 桌面客户端（3.96 MB） | counter（2.27 MB） | 桌面客户端再次打开 | HTML 版场景 4 演示（43 KB） |
  | --- | --- | --- | --- | --- |
  | 本机 | 0.2 | 0.2 | 0.3 | |
  | 50M / 30ms | 1.0 | 0.7 | | |
  | 20M / 50ms | 2.0 | 1.2 | | |
  | 10M / 80ms | 3.6 | 2.3 | 0.4 | 0.3 |
  | 慢 4G（1.6M / 150ms） | 20.6 | 12.1 | 0.6 | 0.6 |
  | 10M，CPU 慢 4 倍 | 4.3 | 3.0 | 1.2 | 0.7（慢 4G 加 CPU 慢 4 倍） |

  wasm 一到齐，流式编译几毫秒就完；Go 启动到第一帧 0.15 秒，CPU 慢 4 倍时 0.75 秒。动画大多 60 帧，CPU 慢 4 倍时有一组掉到 43 帧。内存 27 MB。无头 Chrome 用的是真 GPU（ANGLE Metal，M4）。
- **输入法**：在演示里点"新建局域网"，用 CDP 的 `Input.imeSetComposition` / `insertText` 输入"zhou → zhou mo → 周末"，再输入"夜"（Chrome 自己测输入法就用这个接口，产生的事件和真输入法一样）。逐步截图看画面，同时读隐藏输入框的位置。
- **读屏**：用 CDP 拿整页的无障碍树，读屏软件读的就是这棵树。对照：HTML 版场景 4 演示有 134 个节点、50 个带名字（设备名、成员名、标题都读得到；拖拽的格子还是 div，要补 ARIA 和键盘）。
- **手机**：390×844、3 倍屏、触摸，在 MyGo 自带的 gallery 内容区用手指从下往上拖 400 像素：画面不动；同一处用滚轮：滚了。

复跑：`web/probe/build.sh` 把三份样本编到 `/tmp/dnbweb/site`；`node web/probe/serve.mjs /tmp/dnbweb/site 47610` 起本地服务器；然后 `node web/probe/probe.mjs 'http://127.0.0.1:47610/deneb/?demo=1' --runs 3`（加 `--warm` 量再次打开）、`node web/probe/ime.mjs <url> <截图前缀> 82 221`、`node web/probe/touch.mjs <url> <截图前缀> 300 650 300 250`、`python3 -I web/probe/wasmsize.py <不带 -s -w 编的 wasm> 40`。

## 2. 改用 TypeScript 要多花多少

两种做法都要做的：`/api/v1` 的接法（登录会话、视图、推送、操作）、没有"这台电脑"的画布设计、手机布局、邀请落地页、登录、下载、场景 4 后台、录屏自查。

| | MyGo | TypeScript |
| --- | --- | --- |
| 画布部件 | `cmd/deneb` 是 main 包，要复用就得请客户端线把设备块、连线、卡片抽成包（M3 里它在做"共享给我"），或者 Web 线复制一份，两份 Go 代码会分叉。桌面画布以"这台电脑"为中心，Web 的布局本来就要重写 | 把 `design/demos/v3` 的画布代码（框架、连线和光、动效、样式，约 3300 行）整理成 TS 模块，拆掉录屏剧本和假时钟：3–4 天 |
| 读屏 | 做不了。要做得给 MyGo 补浏览器的无障碍层（把它已有的无障碍树映射成隐藏的 DOM），2 周以上，还是改上游 | DOM 本来读得到，补 ARIA 和键盘操作：2 天 |
| 手机 | 手指滚动要自己写：1–2 天；第一次打开在 4G 下 15 秒以上，只能靠 HTML 落地页先顶着 | 第一次打开 1 秒内 |
| 体积 | 离 15 MB 只差 0.4 MB；请控制线把 `proto` 里的证书校验拆出去，余量才到 1.8 MB | 不是问题（场景 4 演示 43 KB） |
| 录屏自查（§11） | 走客户端线那套 MyGo 无头帧 | `record.mjs`、`motion-check.mjs` 现成能用 |
| 长期 | 三端和 Web 一套代码 | 画面改动要改两处（Go 和 TS），靠同一套设计令牌和录屏对照防分叉 |

**估算**：TypeScript 比 MyGo 多 1–1.5 周（实现计划 M3 风险里写的是 2 周）。MyGo 要是也得解决读屏，反而更慢。

## 3. 推荐

**推荐 Web 全部用 TypeScript**，复用 `design/demos/v3`：

1. 读屏一个字都读不到，而 Web 是公开入口（邀请链接），MyGo 上游没有时间表；
2. 新用户第一站多半在手机上（微信里点开邀请链接）：MyGo 第一次打开 15 秒以上，手指还不能滚动；
3. 设计演示本来就是 HTML 写的，DESIGN 以演示为准，TS 版离设计最近，录屏工具也现成。

代价是多 1–1.5 周，以后画面改两处。

**另一条路**（更看重"只写一遍"时）：落地页、登录、下载用 HTML（秒开，手机和读屏都行），登录后的画布和后台用 MyGo，接受读屏读不到、手机上不好用。

**不管选哪条**，第 3 步都要 `/api/v1`（还没做），可以先请控制线开工。两份文档写得不一样：[`control.md`](control.md) §8 是 `GET /api/v1/view` 加 `POST /api/v1/login`，[`../m4/control.md`](../m4/control.md) §14 是 `GET /api/v1/userview`、网页 `/login` 登录后发 `deneb_session` cookie、多一个 `GET /api/v1/relay-usage`。Web 线按 m4 §14 接（更新、更细）。

## 7. 第 3 步：实现（11-09 凌晨，和设计并行；主会话定的期限 03:45）

### 怎么搭的

- **`cmd/deneb-web`**（Go，只用标准库和 `proto`）：发 `web/app/dist` 的静态文件，别的路径都回 `index.html` 给前端路由；`-control https://… -control-pin sha256:…` 时把 `/api/` 反向代理到控制服务器，TLS 按指纹钉（钉错回 502），Cookie 原样往返，http 监听时去掉 Set-Cookie 的 Secure；`-mock` 时用内存里的假世界答 `/api/v1`（世界和桌面演示一样，验证码 000000，邀请链接 `/i/k3xQ9`），另有两个演示用的假接口（"这台电脑装好登录了""安装命令跑完了"）。
- **`web/app`**（TypeScript，零 npm 依赖）：`node web/app/build.mjs` 用 Node 24 自带的 `module.stripTypeScriptTypes` 把 `src/*.ts` 编成浏览器直接用的 ES 模块，`src/*.css` 拼成 `app.css`，`web/tokens.json` 编成 `tokens.js`。`tsconfig.json` 开 strict；用 `npx -p typescript@5.9 tsc --noEmit -p web/app/tsconfig.json` 查过类型，零错误。
- **画法**：设备块、小球、卡片、托盘、提示条、拖拽、弹簧，用的是设计演示 `design/demos/v3` 的那一份（`src/v3-*.ts`，原样搬来，头一行 `@ts-nocheck`），跑在 `clock.ts`（`motion.js` 的 TS 版）上，所以实现和设计稿是同一份画法，录屏工具也直接能用。设备块用 DOM 画、连线用 Canvas 2D，读屏读得到名字和状态。搬来的代码只加了一处：提示条的"撤销机会没了"回调，用来发 `share.release`。以后再逐个改成有类型的 TS。
- **数据**：`api.ts`（登录、邀请预览、userview、stream 断了 1/2/4 秒重连、ops、relay-usage）、`model.ts`（proto 类型；主人色用和桌面 `ColorFor` 同一个 fnv32a）。连不上服务器时，标题第二行写"连不上服务器，正在重试…"（同桌面端连不上引擎时），接上后换回原来的话；会话失效就回登录页。
