## 1. 几个概念

- **分享**：一台设备 × 一个人，带上开放哪些服务。接收人不进分享方的局域网，他所有的设备都只看得到这一台（DESIGN §2"只给他用这一台"）；只能接收人连过去，这台设备连不了接收人（DESIGN §12 第 12 条"只有他能连你，反过来不行"）。
- **谁能分享**：设备的主人；公共设备由局域网的拥有者分享（§0.2）。
- **公共设备**：属于一个局域网、不属于某个人的设备（打印机、服务器）。拥有者管它：开关服务、谁能用、分享、改名、移出。它不占任何人的位置。
- **设备共享模式（已定，按推荐做）**：场景 4 的后台里，"成员"是管理员（局域网拥有者）分设备的对象，他们只拿到分给自己的那几台，看不到"工作室的设备"全部。要做到这一点，又要能复用邀请、待同意、位置这些现成的东西，推荐给局域网加一个模式：
  - **局域网模式**（默认，场景 5）：和现在一样，成员的设备互相看得见。
  - **设备共享模式**（场景 4）：成员照样通过邀请进来、照样占拥有者的位置、照样有待同意；但成员的设备不加进这个局域网，局域网里只有拥有者的设备和公共设备，成员只通过分享拿到其中几台。成员客户端的侧边栏里，这个局域网出现在"共享给我"下面（"工作室 · 直接连上"），不出现在"我的局域网"里。
  - 这样局域网里仍然只有两种人（DESIGN §2），后台的"成员"就是这个局域网的成员。另一种做法是给后台单独建一张"后台成员"表，多一套邀请和计数，不推荐。
- **分享给局域网模式里的人**：也可以，用来"只给他这一台、不放进局域网"（比如把托盘里的 NAS 拖到 Mia 的小球上）。接收人可以是我视图里看得到的任何人。

## 2. 数据模型（库表第 3 个迁移）

| 表 / 列 | 内容 |
| --- | --- |
| `shares` | `id`、`device`、`receiver`（人）、`sharer`（谁分的：设备主人，或公共设备所在局域网的拥有者）、`created_at`、`state`（`active` / `revoked`）、`revoked_at` |
| `opens` | 不改。分享开放的服务记成 `scope = share/<id>` 的行，和局域网用同一张表、同一套服务目录 |
| `devices.public_lan` | 公共设备所在的局域网，空就是个人设备 |
| `lans.mode` | `lan`（默认）/ `share`（设备共享模式） |
| `shares.hold_until` | 收回后位置留到什么时候：收回时设成 10 秒后（上限兜底），客户端确认撤销窗口关了（`share.release`）就设成当时 |
| 位置数 | 不进库，用启动参数 `-seat-limit`：默认 6，-1 表示不限（自己部署时关掉额度），测试部署可以调成 3（M3 验收） |

**撤销**：收回只把 `state` 改成 `revoked`，行留着。同一台设备再分给同一个人，就把这一行改回 `active`，原来开的服务原样回来，这就是"撤销"（DESIGN §6.5，不另记撤销）。

## 3. 操作

| 操作 | 参数 | 谁能做 | 说明 |
| --- | --- | --- | --- |
| `share.create` | `device`、`person`，可选 `services`（开放哪几项，服务目录里的 key） | 设备主人；公共设备由拥有者 | 返回分享 id。已经分给他了：拒绝，提示"已经有了"（场景 4 第 3 步）。以前分过、收回了：恢复成原样（撤销）。接收人是新的位置、位置又满了：拒绝，`seats_full`，提示"6 个位置都用上了" |
| `share.revoke` | `share` | 分享方 | 收回。能撤销的那几秒里位置先留着（§5） |
| `service.set` | 现有参数，`lan` 换成 `share` 也行 | 分享方 | 开关这次分享里的某项服务 |
| `share.leave` | `share` | 接收人 | 自己不要了（从"共享给我"里拿掉）。分享方那边这一项悄悄消失，不提醒；位置按 §1.4 放出来，不留 |
| `share.release` | `share` | 分享方 | 界面在"已收回 · 撤销"提示条消失时发：撤销窗口关了，留着的位置马上放出来 |
| `device.setPublic` | `device`、`lan`（空 = 改回个人的） | 设备主人，而且是这个局域网的拥有者 | 变成局域网的公共设备，自动在这个局域网里；局域网删除时改回登录它的那个人的 |
| `lan.setMode` | `lan`、`mode` | 拥有者 | 切到设备共享模式时成员的设备移出局域网（他们的分享不受影响）；切回局域网模式不自动加回 |

**和"谁能用"的关系**：分享给某人时，如果在这台设备上拒绝过他，拒绝自动取消（分享就是明确允许）；分享之后再拒绝他，拒绝优先（过滤丢掉，界面写"用不了"），分享本身留着。

## 4. 网络图："分享"这种范围

- 范围 id 是 `share/<分享 id>`。
- **被分享的设备 D**：`Scopes` 里有这个范围，`Open` 是分享开放的服务；`Peers` 里有接收人所有可用的设备，`Scopes` 带上这个范围（加上他们本来就共有的局域网）。
- **接收人的每台设备 E**：`Scopes` 里有这个范围，`Open` 为空，而且**整个范围都不放行进来的连接，包括 ping**；`Peers` 里有 D，`Scopes` 带上这个范围。D 的局域网、D 的其他分享、D 主人的其他设备，E 一概不知道。
- 单向靠接收人一侧的过滤：E 不放行 D 发起的任何连接，D 的回包照常。为此 `Scope` 要多一个字段说明"这一侧只出不进"（见 proto 提案）。在 proto 定下来之前，服务器先按现有字段下发（E 一侧 `Open` 为空），这时 D 只能 ping 到 E，别的连接都过不了 E 的过滤。
- 暂停、`refusedByMe`、`refusedByPeer`、`pausedScopes` 都照现有规则作用在分享范围上。
- 收回后，D 和 E 的网络图里马上没有这个范围；如果它们之间没有别的共同范围，就互相看不见（验收"收回后 2 秒内不通"）。

## 5. 位置的限制（定价文档 §1.4、§1.5）

- **算法**：X 占用的位置 = X 自己 + X 建的局域网里已加入的人 + X 分享设备给的人（生效中的分享，加上收回不到几秒、还能撤销的），同一个人只算一次。公共设备不占；待同意、已邀请没接受的不占；别人分给 X 的不占 X 的。
- **只在"加一个新的人"时检查**：`invite.accept`、`member.approve`、`share.create`。已经在名单里的人再分一台、再拉进另一个局域网，照常。
- **满了时**：
  - `share.create`、`member.approve`：拒绝，`seats_full`，提示"6 个位置都用上了"（数字按部署的额度）。
  - `invite.accept`：不拒绝，人变成"待同意"，界面画虚线球，拥有者点它时先腾位置（§1.5 第 5 条）；`InvitePreview` 和对方的视图里写清"X 的位置满了，腾出来就能加入"。
  - 已经在名单里的人和设备照常，不断线。
- **收回后先留着**（主会话 11-08 定）：收回分享后，这个人的位置一直留到界面告诉服务器"撤销窗口关了"（提示条消失时发 `share.release`），这期间撤销一定成功；10 秒只作上限，防客户端掉线没发确认。之后位置才放出来（§1.5 第 7 条）。这样撤销按钮一消失就能加新人，不会再空等几秒。
- **视图里**：`Seats{used, limit, enforced, people}`，再加"还能加几人"；界面按 §1.5 显示（只剩 2 个以下才显示数字）。
- **测试部署**：启动参数 `-seat-limit 3`，M3 验收用。

## 6. 中转站（定价文档 §2.3）

- 分享范围用的中转站：分享方自己的中转站（主人是分享方的），没有就用公共的；M3 时只有 hk-spare 上的那一个（主人是 kittors），找不到时退回部署的默认中转站，保证连得通。
- "分享方的中转站只服务这一条"要靠中转站准入（M4，`/relay/v1/admit`）；M3 先在网络图里把这个范围的 `relays` 写对，M4 有了多个中转站后再验一次。

## 7. 视图（给界面和 Web）

- **分享方**：自己设备的 `DeviceView` 里列出这台分出去给了谁（分享 id、接收人、开放的服务、时间）；接收人进 `People`。
- **接收人**：新的"共享给我"列表，每项是一次分享：分享 id、设备（名字、种类、系统、正式名、地址、在线）、来自谁（分享方这个人，公共设备写局域网名"工作室"）、开放给我的服务。看不到这台设备在哪些局域网、还分给了谁、关着的服务。
- **公共设备**：`DeviceView` 写明属于哪个局域网；别的成员看到的是"工作室的设备"。
- **位置**：见 §5。

## 8. Web 后台要的接口（场景 4，`/api/v1`，Web 线开工时做）

浏览器不进局域网，凭登录得到的会话（浏览器登录页现成的那套，加一个会话 cookie）调用户接口：

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/view` | 这个人的用户视图（和设备收到的同一个 `UserView`，没有"这台电脑"） |
| `GET /api/v1/stream` | 视图变了就推一份（NDJSON，和设备的长连接一样的帧，只是没有网络图） |
| `POST /api/v1/ops` | 同一套操作；没有发起的设备，所以 `lan.create`、`invite.accept` 不会顺带加设备 |
| `POST /api/v1/login`、`/logout` | 浏览器登录、退出（复用现有登录页的邮箱和验证码） |

场景 4 的交互都落在现有操作上：设备格子拖到成员行上、成员拖到设备上 = `share.create {device, person}`；展开成员看他的设备 = 视图里按接收人分组的分享；点 × = `share.revoke`；"撤销" = 再发一次 `share.create`（恢复原样）；拖给已经有它的人 = 服务器回"已经有了"。

## 9. proto 提案（发给引擎线，它修完 M2 再定）

全部是新增，旧字段含义不变：

- `ShareID`；`ScopeID` 的 `share/<id>` 形式（`ShareScope(id)`、`ScopeID.Share()`）。
- `Scope` 加 `Kind`（`lan` / `share`）和 `NoInbound bool`：为真时这一侧不放行这个范围里对端发起的任何连接（包括 ping），只出不进。接收人一侧为真，被分享的设备一侧为假。旧引擎不认识就照现有规则处理（`Open` 为空），只差 ping。
- `Node` 加 `PublicLAN LANID`（公共设备属于哪个局域网）。
- 视图：`DeviceView.Shares []ShareView`（我分出去的）、`DeviceView.PublicLAN`、`UserView.SharedWithMe []SharedDevice`（共享给我）、`Seats.Left`、`InvitePreview.SeatsFull`、`LANView.Mode`。
- 操作：`share.create`、`share.revoke`、`share.leave`、`share.release`、`device.setPublic`、`lan.setMode`；`OpArgs` 加 `Share`、`Services []ServiceKey`、`Mode`；`OpOutput` 加 `Share`。
- `Features` 加 `share`、`publicDevice`、`seats`。

## 已做的（11-08，本机）

- **库表第 3、4 个迁移**：`shares` 表（一台设备 × 一个人，收回只改状态、行留着）、`devices.public_lan`；`shares.hold_until`（收回后位置留到什么时候）、`lans.mode`。
- **分享**（`control/share.go`）：`share.create`（只有设备主人，公共设备只有拥有者；不能分给自己；已经有了回"已经有了"；收回过的再分一次就原样恢复，这就是撤销；分享时自动取消对这个人的拒绝；位置满了回 `seats_full`）、`share.revoke`（只改状态，位置留 10 秒）、`service.set` 带 `share`（按分享开关服务，和局域网的开关共用一套逻辑）、`device.setPublic`。
- **网络图**：按 §4 下发 `share/<id>` 范围：被分享的设备看得到接收人所有可用的设备，开放分享的服务；接收人的设备只看得到这一台，`noInbound` 为真、`Open` 为空；接收人自己的设备之间不会因为分享互相看见；暂停、拒绝、`pausedScopes` 照常作用。每个范围都带 `kind`（`lan` / `share`），公共设备的节点带 `publicLAN`。中转站按 §6 选（M3 只有 hk）。
- **视图**：`sharedWithMe`（共享给我：设备只露出能用的部分，`fromLAN` 写公共设备所在的局域网）、`DeviceView.shares`（管这台设备的人看得到分给了谁）、`DeviceView.publicLAN`、`seats.left`、`InvitePreview.seatsFull`；功能列表是 `proto.M3Features`（多了 `share`、`publicDevice`、`seats`）。
- **公共设备**：`deviceSetPublic`（设备主人且是局域网拥有者；只留在这个局域网里，加不进别的）；之后由拥有者管理，别的成员动它时提示"这是「工作室」的公共设备，只有拥有者能…"；局域网删除或把它移出局域网时还给登录它的人。

- **设备共享模式**（主会话 11-08 定）：`lan.setMode`（拥有者）。共享模式的局域网只放拥有者的设备和公共设备，加载、网络图、视图三处都把关；切过去时成员的设备移出，成员之后接受邀请、`lan.addDevice` 都不会把设备放进来；成员看这个局域网只有名字、拥有者和自己，拥有者看得到全部成员和设备。
- **接收人自己不要**：`share.leave`，分享方的视图里这一项悄悄消失。

## 主会话的决定（11-08）

3. **收回后位置留多久**：不固定 10 秒。位置留到客户端确认"撤销窗口关了"（提示条消失时发确认），10 秒只作上限兜底；撤销就恢复原样。这个确认和界面线约好。
   - **和界面线约定的发法**（11-08 确认）：点收回立刻发 `share.revoke`，提示条"已收回 X · 撤销"；点撤销就发 `share.create`（同设备、同人、同服务），不发 release；提示条走了而没点撤销，就发 `share.release {share}`。"走了"包括四种：到时间、被新提示条顶掉、切画布、主窗口藏到菜单栏。M3 界面开工时接，在那之前客户端不会发这几个操作。
