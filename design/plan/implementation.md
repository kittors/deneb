第 2 条还有两个小问题：

- **端口**：hk-155 的 80、443 已被已有服务占用。控制服务器在 Docker 里听一个高位 TCP 端口，开工时用只读命令确认它空闲。容器用宿主网络模式（`--network host`），只监听端口，Docker 不去改宿主的防火墙规则。
- **证书和域名**：推荐先用自签证书，客户端内置它的指纹，零依赖，也不碰 nginx。你如果有空的子域名（例如 `deneb.example.com`），可以用 DNS 验证签正式证书；也可以在 hk-155 的 nginx 里加一段反代，但这要改已有服务，你点头才做。

### 0.3 开工时要你点头的操作

按全局规则，下面这些动手前都要你确认。哪一条都不改服务器的网络配置、防火墙和已有服务。

1. **仓库**：项目目录现在不是 git 仓库。建议开工时初始化，推到 GitHub（`kittors/deneb`，和 `go.mod` 里的模块名一致），CI 用 GitHub Actions。提交和推送仍然等你开口。
2. **挪目录**：根目录的界面原型要挪到 `cmd/deneb/`（§2.8）。别的会话可能正在改这几个文件，挪之前先和它们对齐。
3. **hk-155**：Docker 里跑控制服务器和我的一个 Linux 节点（用户态，不建网卡），用两个高位端口，限制 CPU 和内存。
4. **hk-spare**：Docker 里跑阿杰的一个 Linux 节点（用户态）。现成的 derper 只当它的普通客户端用，不改配置。
5. **Windows 测试机**：跑用户态节点和命令行，不改网络配置，用完就停掉进程。
6. **本机 Mac**：默认用户态，不改系统。验收内核网卡模式的那一轮，照 multi-lan-tech §6.8 的做法另外确认一次。

## 1. 一页总览

Deneb 分四块：**控制服务器**管账号、局域网和规则，不碰流量；**组网引擎**每台设备一个，负责连接和隔离；**桌面客户端**是 MyGo 自绘的界面，macOS、Windows、Linux 一个样；**Web 后台和 Web 客户端**是同一套 MyGo 界面编译到浏览器。中转站直接用 DERP。全部用 Go 写，放在一个仓库里，各端共用同一套类型。

```
浏览器：Web 后台、Web 客户端（MyGo 编译到浏览器）
  │  用户接口 /api/v1
  ▼
控制服务器 deneb-control
  管：人、局域网、成员、邀请、设备、服务开放、谁能用、分享、中转站
  算：地址分配，每台设备的网络图（谁看得见谁），每个人的位置
  存：SQLite
  │  设备接口 /device/v1：TLS 长连接，推网络图和用户视图（同一个版本号）
  ▼
每台电脑
  引擎 denebd：一把密钥、一个地址、一个 UDP 端口、每个中转站一条连接
    内核网卡（桌面默认），或用户态网络栈（服务器、没权限、有冲突时）
    │  本机接口：Unix 套接字 / 命名管道
    ▼
  界面 deneb（MyGo：窗口 + 菜单栏）

引擎 ⇄ 引擎：WireGuard，直连优先；连不上就经中转站（DERP，只转发密文）
中转站 ⇄ 控制服务器：准入，只让该用它的设备用（M4）
```

| 里程碑 | 做到什么 | 粗估 | 在哪验收 |
| --- | --- | --- | --- |
| **M1** | 两个人、两个局域网、一台电脑同时在两个局域网；现有界面由真实账号和真实连接驱动 | 6–8 周（三块能并行，最快约 4 周） | 本机 Mac、hk-155、hk-spare、Windows 测试机 |
| **M2** | 局域网模式做完整：场景 1、3、5 全部由真实事件驱动；待同意、需要重新登录、连不上的原因；macOS 菜单栏 | 4–5 周 | 同上，另加换网、睡眠、坏线路 |
| **M3** | 设备共享模式：分享给某个人、共享给我；Web 后台（场景 4）；Web 客户端；位置的限制 | 5–6 周 | 同上，另加浏览器 |
| **M4** | 中转站：公共的兜底、自己的拖进来（场景 2）；多个中转站、准入、限速、用量 | 4–6 周；家里的设备当中转站另加 3–4 周 | hk-spare、hk-155 各一个 Deneb 自己的中转站 |
| **M5** | Windows、Linux 完整客户端：内核网卡、系统服务、托盘 | 4–6 周 | Windows 测试机；Linux 桌面虚拟机 |
| **M6** | 普通人装得上：签名公证、安装包、自动更新、首次引导、和代理软件共存 | 3–4 周 | 三个平台的干净系统各装一遍 |
| **M7** | 公测：加位置的付费、地址池扩容、高可用和备份、监控、安全审查 | 4–6 周 | 外部测试用户 |

M3 和 M4 可以并行，M5 可以在 M2 之后并行开始。串行合计约 7–10 个月，按这样并行约 5–7 个月。

## 2. 总体架构

### 2.1 模块和边界

| 模块 | 负责 | 不负责 | 对外接口 |
| --- | --- | --- | --- |
| **控制服务器** `deneb-control` | 账号和登录；局域网、成员、邀请；设备登录和地址；服务开放（按设备 × 局域网）；谁能用（按设备）；分享；每个人的位置；中转站登记和准入；算出每台设备的网络图，实时推送 | 不碰流量；不存设备私钥；不存画布上的摆放 | 用户接口 `/api/v1`（给 Web）；设备接口 `/device/v1`（给引擎，长连接）；中转站准入 `/relay/v1/admit`（M4） |
| **组网引擎** `denebd` | 设备密钥；到控制服务器的长连接（本机只有它连）；按网络图建立 WireGuard 隧道；直连和中转之间切换；隔离过滤；名字和 DNS；内核网卡或用户态网络栈；绑物理网卡 | 不画界面；不判断权限：权限由控制服务器判，过滤只执行下发的表 | 本机接口（§2.6.2）；命令行 `deneb` 也走它 |
| **桌面客户端** `deneb` | 窗口和菜单栏（托盘）；把用户的世界画成画布；把拖拽变成操作；摆放存在本机；打开服务（远程桌面、共享文件夹、网页） | 不直接连控制服务器；不持有密钥 | 只用本机接口 |
| **Web 后台和 Web 客户端** `deneb-web` | 在浏览器里看和管：登录、接受邀请、局域网和设备、分享、场景 4 的后台 | 浏览器不进局域网，不建立连接 | 用户接口 `/api/v1` |
| **中转站** | DERP：按设备公钥转发密文，另带 STUN | 不认识局域网，看不到内容 | DERP 协议（现成） |

两条贯穿全局的规则：

- **只有控制服务器判断权限。** 客户端和 Web 只说"我想做什么"；被拒绝就退回原状，并说一句原因。
- **同一个版本号。** 控制服务器每变一次，就给受影响的设备推一个新版本。界面显示的和引擎在用的出自同一个版本，不会出现"画面上还连着，其实已经被移出"。

### 2.2 控制服务器

**数据**（M1 就建好的表；标 * 的字段或表到对应里程碑才启用）：

| 东西 | 主要字段 | 说明 |
| --- | --- | --- |
| 人 | 显示名、首字、英文短名、登录身份 | 英文短名用在名字 `设备.主人.deneb.internal` 里，默认取邮箱前缀，"更多"里能改。主人色不存服务器：在每个人自己的画面上"我"都是蓝色（DESIGN §3.3），别人按固定规则分配，同一个人在我的所有局域网里颜色相同 |
| 设备 | 主人（人；*或局域网，即公共设备）、名字、英文短名、种类（电脑、NAS、游戏主机…）、系统、三把公钥、IPv4、IPv6、上报的端点、常驻中转站、在线、*登录到期、状态（正常 / *待同意） | 一台设备一个地址，进几个局域网都用它。英文短名默认取系统主机名 |
| 局域网 | 名字、拥有者、*设置（新成员、新设备要不要同意） | |
| 成员 | 局域网、人、身份（拥有者 / 成员）、状态（已邀请 / *待同意 / 已加入）、加入时间 | 只有两种身份（DESIGN §2） |
| 局域网里的设备 | 局域网、设备、加入时间、暂停 | 一台设备可以在几个局域网里。暂停由设备自己设，只影响它自己 |
| 开放 | 设备、范围（局域网，*或分享）、服务种类（远程桌面、共享文件夹、网站、命令行、游戏…）、端口和协议、开关 | 对应 multi-lan-tech §4 的"开放表" |
| 谁能用 | 设备、人 | 按设备记（DESIGN §6.5）：在游戏主机上不让 Mia 用，不影响这台电脑 |
| 邀请 | 局域网、邀请人、链接令牌、到期、状态 | 邀请了还没接受的人不占位置 |
| *分享 | 设备、接收人、分享人、开放哪些服务、状态 | M3。单向：只有接收人能连这台 |
| 中转站 | 地点名（"香港"）、来源（我的服务器 / *家里的设备 / *公共）、主人、DERP 地址、STUN 端口、*限速 | M1 登记 hk-spare 上现成的 derper |
| 局域网用的中转站 | 局域网、中转站、顺序 | 对应"中转表"。M1 所有局域网共用登记的那一个 |
| *中转用量 | 中转站、设备、日期、字节数 | M4。只按设备记总量，用来限速、排障和给主人看"这个月替周末联机转了多少"，不记谁和谁说话（定价文档 §2.3、§2.4） |
| 部署设置 | 地址段、IPv6 ULA、额度开关 | 部署时生成一次；别人自己部署时额度关掉 |

**位置不单独存**，按定价文档 §1.4 的规则从成员、分享和后台成员算出来：同一个人只算一次，"已加入"才占，"已邀请"和"待同意"不占。M1 起就算（命令行能看），M3 起才限制。

**两份下发，同一个版本号：**

- **网络图**（给引擎）：每台设备一份，只含"和它至少有一个共同范围"的对端，每个对端带上共同的范围。这是隔离的第一层："看不见"就连不上。
- **用户视图**（给界面）：每个人一份，含他所有的局域网、成员、设备、托盘、服务、谁能用、分享和邀请。引擎原样转给界面。无界面的节点（服务器、NAS）默认不收用户视图，命令行用到时再拉，这样服务器上平时不存主人其他局域网的信息。

"谁看得见谁"是安全关键代码：任意拓扑下，设备只拿到和它有共同范围的对端，而且共同范围只含它真正在的那几个。M1 起用随机生成拓扑的属性测试守住，规则和 multi-lan-tech §3.5 第 1 层一致。

**地址和名字**：照 multi-lan-tech §3.3、§3.4 执行。部署时在 `10.0.0.0/8` 里随机取一个 `/16`，避开 `10.0`、`10.1`、`10.10` 这类常用段；不用 `100.64.0.0/10`，也避开 Clash 的 `198.18.0.0/15`。DNS 服务地址也放在这个 `/16` 里。设备删除后，地址冷却 30 天再复用。正式名用 `设备.主人.deneb.internal`，短名只有唯一时才解析。

**谁能做什么：**

| 操作 | 谁能做 |
| --- | --- |
| 新建局域网；改名、删除 | 谁都能新建；改名、删除只有拥有者能做 |

### 2.3 组网引擎

方案照 multi-lan-tech §4，这里不重复。要点：一个引擎服务所有局域网；三张表（对端表、开放表、中转表）由控制服务器下发；加入、暂停、退出一个局域网只改表；隔离分四层；发往公网的包绑物理网卡。

| 包 | 内容 | 从哪来 |
| --- | --- | --- |
| `engine/controlclient` | 设备登录、长连接、上报端点、收网络图 | 新写 |
| `engine/netmap` | 三张表，按版本整份替换 | PoC [`node.go`](../../poc/multi-lan/node.go) 的 `applyNetmap` |
| `engine/magicsock` | 一个 UDP 端口加每个中转站一条连接：探测、选路、切换 | 见下面的"底座选型" |
| `engine/filter` | 不转发、按范围放行服务、放行回包 | PoC [`filter.go`](../../poc/multi-lan/filter.go) 和它的测试 |
| `engine/names`、`engine/dns` | 名字规则；只接管 `deneb.internal` | PoC `names.go`、`dns.go`；三个平台的 DNS 管理复用 Tailscale 的 `net/dns` |
| `engine/tun`、`engine/router` | 内核网卡和路由：macOS 一条 `/16`，Windows、Linux 按对端 `/32` | PoC `tun_darwin.go`；复用 Tailscale 的 `wgengine/router`、`net/tstun` |

**底座选型（M1 第一周定）。** PoC 的小号 magicsock 有 800 行，跑通了，但没有单独的探测密钥、端口映射（UPnP、NAT-PMP），也没有多中转站和"只在有流量时心跳"。两条路：

- **甲（先试这条）**：把 Tailscale 的 `wgengine/magicsock` 当库用，把我们的网络图转成它认识的节点结构喂给它，过滤换成我们自己的。它成熟，但接口和 Tailscale 的数据结构绑得紧，跟上游升级时要一起改。
- **乙**：在 PoC 的 magicsock 上补齐。代码都在自己手里，补齐要多 2–3 周。

花三天做对照：甲能不能在不改 Tailscale 源码的前提下接上三张表，并在 colima 里通过 PoC 的隔离用例（借道、伪造来源）和启动测试（0.12 秒经中转应答，0.63 秒换直连）。通过就选甲，否则选乙。不管选哪条，引擎对外的接口都不变。

**两种模式**：桌面默认用内核网卡；服务器、没有管理员权限、检测到地址冲突时改用用户态。M1 只有 Mac 有内核网卡（PoC 已验证），Windows（Wintun 加 NRPT）和 Linux（tun 加 systemd-resolved）放在 M5。

**时间参数**：M1 用 1 秒心跳、2.5 秒不信任。multi-lan-tech §6.2 里，这组参数下直连断后只中断 2.35 秒，TCP 很快恢复。M2 改成只在有流量时心跳以省电，并按丢包率和延迟选路：§6.8 那种直连有回应、却丢了 20% 包的情况，要切到中转。

### 2.4 桌面客户端

**每台电脑两个进程：**

- **引擎 `denebd`** 常驻。内核网卡模式下它是系统服务（macOS 的 launchd 守护进程、Windows 服务、Linux 的 systemd 服务），以管理员权限运行；用户态模式下由界面以普通用户身份启动。关掉窗口连接不断，界面崩了连接也不断。
- **界面 `deneb`** 是 MyGo 应用，普通用户权限。主窗口和菜单栏面板是同一个进程里的两个窗口，看同一份数据。

**三个平台的差异**都在引擎和安装上，界面一个样（DESIGN §8）：

| | macOS | Windows | Linux |
| --- | --- | --- | --- |
| 网卡 | utun（PoC 已验证的做法）；正式发布用网络扩展还是特权守护进程，M6 定 | Wintun | `/dev/net/tun` |
| 路由 | 一条 `/16` | 按对端 `/32` | 按对端 `/32` |
| DNS | `/etc/resolver/deneb.internal`，或网络扩展的 matchDomains | NRPT | systemd-resolved 的 `~deneb.internal`；没有它时用用户态 |
| 绑物理网卡 | IP_BOUND_IF（PoC 已实现） | IP_UNICAST_IF | SO_BINDTODEVICE |
| 引擎怎么跑 | launchd 守护进程 | Windows 服务 | systemd 服务；服务器上可以只装引擎和命令行 |
| 托盘 | 菜单栏 | 通知区 | AppIndicator（要装 `libayatana-appindicator3`） |
| 安装包 | 签名公证的 `.app`，引擎在里面 | 安装程序，带引擎和 Wintun | `.deb`、`.rpm`；另有只含引擎的服务器包 |

**MyGo 里现成能用的**（v0.7.4 文档）：从别的 goroutine 改状态（`Window.Update`）、托盘（`NewTray`）、贴着锚点弹出的窗口（Flyout，用来做菜单栏面板）、系统凭据存储（`Secrets`）、自定义链接（`OnOpenURL`，邀请链接用 `deneb://`）、开机启动（`SetOpenAtLogin`）、单实例、联网和睡眠事件、自动更新，以及把引擎当辅助程序打进安装包并一起签名。MyGo 默认的安装包只给当前用户装、不要管理员权限，所以装系统服务和网卡驱动要自己做（见 M6 的风险）。

### 2.5 Web 后台和 Web 客户端

**用同一套 MyGo 界面编译到浏览器。** MyGo 能把原生界面编成 WebAssembly，`mygo build -platform web` 出一个静态站点。它自己的例子是 8–10 MB，压缩后 2.2–2.6 MB。好处是设备块、小球、连线、拖拽和弹簧动效只写一遍，三端和 Web 一个样。

- **Web 客户端**：浏览器不进局域网，只能看和管：登录、打开邀请链接后加入、看局域网和设备、拖进拖出、服务开关、谁能用、分享，还有引导下载客户端。朋友发来的邀请链接在浏览器里打开，所以新用户的第一站就是它。
- **Web 后台**：场景 4 的列表后台：设备格子网格、成员行，把设备拖到成员身上就是分享。它和 Web 客户端是同一个站点的两个入口，按身份显示。
- 两者都走用户接口 `/api/v1`，凭浏览器登录得到的会话。数据和桌面一样是用户视图，只是没有本机引擎：画面上没有"这台电脑"，连线也不是本机看到的状态（怎么画见 §5）。
- **退路**：M3 第一周先量体积和首屏时间。超过 15 MB 或首屏超过 3 秒，就改用 TypeScript 写 Web，复用 `design/demos/v3/` 的代码。另有两个已知限制：屏幕阅读器还读不到画在 canvas 里的内容；内嵌字体要等浏览器加载完才画。

### 2.6 接口

#### 2.6.1 控制服务器 ↔ 引擎（设备接口）

- **登录一台设备**：引擎生成三把密钥：控制面认证用的机器密钥、WireGuard 的节点密钥、探测用的密钥。私钥只存在本机（守护进程的受保护文件，或系统凭据存储）。引擎向控制服务器要一个登录链接，界面在浏览器里打开它；命令行则把链接打印出来，在别的设备上打开也行。登录完成后，这台设备就记在这个人名下。客户端里没有账号密码框。
- **长连接**：走 TLS，引擎用机器密钥签名换一个短期令牌。连上后，服务器先推当前版本的网络图（和用户视图），之后每变一次推一次；引擎上报端点、常驻中转站和自己暂停了哪些局域网。断线重连时带上已有的版本号，服务器只补后面的。
- **控制服务器连不上时**，引擎照上一份网络图继续工作，已经连上的设备不断。

```go
// NetMap is what the control server sends one device. It holds only the
// peers this device shares a scope with, because a peer it cannot see is a
// peer it cannot reach: the first of the four layers of isolation.
type NetMap struct {
	Version uint64
	Self    Node
	Peers   []Peer
	Scopes  []Scope // the LANs (and, from M3, shares) this device is in
	Relays  []Relay // the relays those scopes use
}

type Peer struct {
	Node
	Scopes []ScopeID // only the scopes both devices are in, so a peer never learns of the others
	// Refusals are kept per device (DESIGN §6.5) and both ends are told: the
	// refused end stops dialing, and the refusing end's filter drops it anyway.
	RefusedByPeer bool // the peer's owner refused my owner on it
	RefusedByMe   bool // my owner refused the peer's owner on me
}

type Node struct {
	DeviceID  DeviceID
	NodeKey   key.NodePublic
	DiscoKey  key.DiscoPublic
	Addrs     []netip.Prefix   // one IPv4 /32 and one IPv6 /128, the same in every LAN
	Endpoints []netip.AddrPort // as the device last reported them, for hole punching
	HomeRelay RelayID
	Online    bool
}

type Scope struct {
	ID     ScopeID   // "lan/<id>", or "share/<id>" from M3
	Open   []Service // what this device opens to the other members of the scope
	Paused bool      // set by this device: the engine stops the scope's packets and names at once, then reports it, so a pause never waits on the server
}
```

#### 2.6.2 引擎 ↔ 界面（本机接口）

HTTP 加 JSON，走 Unix 套接字（macOS、Linux）或命名管道（Windows）。只有这台电脑上登录 Deneb 的那个系统用户能连。

| 路径 | 作用 |
| --- | --- |
| `GET /v1/state` | 一份快照：用户视图、到每个对端的连接、引擎自己的状态（登录了没有、控制服务器连着没有、内核网卡还是用户态） |
| `GET /v1/watch` | 事件流：快照一变就推新的，带版本号；连接状态单独推，每秒最多几次 |
| `POST /v1/ops` | 一个操作（见下表）。引擎转给控制服务器，带幂等键，返回生效后的版本号或拒绝原因 |
| `POST /v1/login`、`POST /v1/logout` | 拿登录链接；退出 |
| `POST /v1/lan/pause` | 暂停、恢复一个局域网：引擎立刻改表，再告诉控制服务器 |
| `GET /v1/resolve`、`GET /v1/ping` | 解析名字、测连接，给命令行和卡片的"更多"用 |
| `GET /v1/services` | 本机在听哪些常见服务（远程桌面、屏幕共享、共享文件夹、命令行、网页），给"开放给大家的"列表用 |
| `POST /v1/open` | 打开对方的一项服务。内核网卡模式下直接给名字和端口；用户态模式下先建一条本地端口映射，返回 `127.0.0.1:端口` |

```go
// PeerPath is how this computer reaches one peer right now, as the engine
// sees it. The client, not the engine, turns it into words and tracks, so
// the debounce rules live in one place and are tested once.
type PeerPath struct {
	DeviceID DeviceID
	Kind     PathKind // Direct, Relay, Connecting, Unreachable, Offline, Paused, Refused
	Relay    RelayID  // when Kind is Relay
	RTT      time.Duration
	Loss     float32   // over the last 10 s: an answering direct path can still be a bad one
	Since    time.Time // when this kind began; scene 3 counts "已连接 2:14:08" from it
}
```

#### 2.6.3 控制服务器 ↔ 中转站

M1 用你现成的 derper。它们没开客户端验证，任何 DERP 客户端都能用，Deneb 不去改。

M4 起，Deneb 自己的中转站都带准入：derper 的 `--verify-client-url` 指向控制服务器，每有设备连上来就问一次该不该放行。规则照定价文档 §2.3：

- 公共中转站：所有登录了 Deneb 的设备都能用，按每条连接限速。
- 我的服务器、家里的设备：只放行主人拖它进去的那些局域网里的设备，以及主人分享出去的设备和它的接收人。你现成的 derper 不改；想让它带准入，就换成 Deneb 提供的中转站镜像。
- 中转站每天把各设备的用量报给控制服务器，只报总量。

### 2.7 现有界面怎么从演示数据换成真实数据

**现状**：根目录的原型只画一个局域网（场景 5 的画面）。业务数据（人、成员、设备、服务、谁能用、托盘、中转站）和界面状态（位置、拖拽、动画、布局缓存）放在同一个 `app` 结构体里；演示数据写死在 `newApp()`（[`model.go`](../../model.go)）；界面上的操作直接改这些数据。

**拆法**（M1 第一周先做这一步，演示模式下画面一个像素都不变）：

1. **业务数据变成只读快照。** 新建 `client/model`，类型取自 §2.6。快照整份替换，从不原地修改；里面不放 MyGo 的类型，主人色存编号，由界面映射成颜色。
2. **界面只认一个接口：**

   ```go
   // Store is where the client's world comes from: the demo's or the
   // engine's. The view reads Snapshot on the main thread. Subscribe's
   // callback runs on another goroutine and must hand the snapshot over
   // through Window.Update, because the view reads state without locks.
   type Store interface {
   	Snapshot() *model.Snapshot
   	Subscribe(func(*model.Snapshot)) (cancel func())
   	Do(ctx context.Context, op model.Op) (version uint64, err error)
   }
   ```

   它有两个实现。`demoStore` 装着现在 `newApp()` 里的数据，外加一个小模拟器（"网络变了"、"Leo 加入"），给演示模式、录屏和现有测试用。`liveStore` 连本机接口。`deneb --demo` 用前一个。
3. **`app` 只留界面状态。** `device` 拆成两半：位置、拖拽和动画留在界面这边，按设备 id 记；名字、种类、主人、路径、服务、谁能用每帧从快照读。
4. **新快照来了就对账：** 新出现的设备找空位放下，轨道从这台电脑长出来；消失的设备收回轨道；路径变了，连线按场景 1 的画法换状态；有人加入，标题的小球叠里弹出他。这些动画原型里都有。
5. **操作先动画、后确认：** 松手后照常播放动画，同时发出操作，在快照上先叠一层"等确认"。服务器确认后，新快照里已经带上这个变化，叠层撤掉；被拒绝（没权限、位置满了、断网）就用 Smooth 退回原处，提示条说一句原因。
6. **摆放存本机**（DESIGN §6.2）：按"局域网 × 设备"存，下次打开还在原处。
7. **连接状态要防抖：** 刚开始连接的 2 秒里只显示"正在连接…"，之后显示当时稳定的状态；直连和经中转之间的变化要持续 2 秒才换画面（multi-lan-tech §7）。防抖只在 `liveStore` 里做，也只在那里测。M2 和"先通后快"的画法一起再定一次。

**测试一起改：** 现有的 4 个测试文件（`view_test.go`、`interact_test.go`、`links_test.go`、`tray_test.go`）改用 `demoStore`，照常通过。另加一组 `liveStore` 的测试，用假的本机接口喂事件，检查对账和防抖。用 `TestFrames` 在改造前后各出一套帧，逐帧比对，证明演示模式下画面没变。

### 2.8 仓库布局

```
cmd/deneb/            桌面客户端（根目录现在的 *.go 挪到这里）
```

## 3. 里程碑

### M1 · 两个人、两个局域网、一台电脑同时在两个局域网

**做到什么程度**

现有界面由真实账号和真实连接驱动。验收拓扑：

| 设备（界面上的名字） | 机器 | 主人 | 在哪些局域网 | 运行方式 |
| --- | --- | --- | --- | --- |
| 这台电脑 | 本机 Mac | 我（kittors） | 工作室、周末联机 | 界面加引擎；用户态，确认后加测一轮内核网卡 |
| 构建服务器 | hk-155 的 Docker | 我 | 工作室；在周末联机的托盘里 | 引擎加命令行，用户态 |
| 阿杰的台式机 | Windows 测试机 | 阿杰 | 周末联机 | 引擎加命令行，用户态 |
| 阿杰的 NAS | hk-spare 的 Docker | 阿杰 | 周末联机 | 引擎加命令行，用户态 |

"工作室"由我新建；"周末联机"由阿杰新建，再邀请我加入。两个人各当一回拥有者、一回成员，邀请的两头都走一遍。阿杰看不到工作室，也不能借我的电脑摸到构建服务器。两个人用的是测试账号，在控制服务器里真实注册、真实登录，不是写死的演示数据。

- **控制服务器 v0**：人（邮箱加验证码，测试账号）、局域网、成员、邀请链接、设备登录和地址分配、局域网里的设备、服务开放、谁能用、中转站登记（hk-spare 上现成的 derper）、网络图计算和推送。部署在 hk-155 的 Docker 里。另有两个服务端直接出的简单网页：登录页和邀请落地页。它们不是 Web 客户端。
- **引擎 v0**：底座按 §2.3 选定；接上控制服务器；三张表热替换；三个平台的用户态；Mac 的内核网卡；绑物理网卡；本机接口；命令行 `deneb login | status | lan | ping`。
- **界面**：按 §2.7 接上真实数据。侧边栏列出我的局域网，点一下切换画布，切换只换画面，不碰任何连接。托盘拖进、拖出真实生效；卡片里的服务开关、谁能用真实生效；"打开"真能打开对方的服务；连线状态来自引擎。"邀请朋友"复制一条链接；打开邀请链接（`deneb://`）会弹出场景 3 那张"邀请你加入"的卡片。在这台电脑上新建或加入局域网时，这台电脑跟着加进去（它本来就不能移出，DESIGN §6.2）。首次打开时只有一个"登录"按钮，点了去浏览器里登录。

**不做**：分享给某个人、拖中转站、场景 3 的"全部"视图和局域网开关、待同意、登录到期、位置的限制、菜单栏、Windows 和 Linux 的界面和内核网卡、Web 客户端和 Web 后台。

**怎么验收**

先在 colima 里搭一套假拓扑：控制服务器、4 个用户态节点、一个 derper，用 Docker 网络模拟两层 NAT。每次改动都跑，全过了再上真机。真机验收逐条做，结果记在 `design/plan/m1-acceptance.md`：

1. **登录**：Mac 上第一次打开，点"登录"，在浏览器里用测试账号登录，回到客户端后侧边栏底部是 kittors。hk-155、hk-spare、Windows 上执行 `deneb login`，各打印一条链接，在本机浏览器里打开并登录；hk-spare 和 Windows 登阿杰的账号。
2. **建局域网、加设备**：新建"工作室"，这台电脑已经在里面；构建服务器出现在托盘，拖进画布，连线从"正在连接…"变成"直接连上"或"经香港中转"。
3. **邀请**：阿杰在 Windows 上执行 `deneb lan invite 周末联机` 拿到链接；我在 Mac 上打开它，弹出"阿杰邀请你加入「周末联机」"，点"加入"后侧边栏多一行，画布上出现阿杰的两台设备。
4. **同时在两个局域网**：Mac 同时连着构建服务器和阿杰的两台设备，每台挂一条长连接（每 100ms 一行，同 PoC 的 `/tick`）。来回切换侧边栏 10 次，三条连接都不断，停顿不超过 0.5 秒。两个局域网的标题都写"都连上了"。
5. **互不打扰**：在 Windows 上把阿杰的 NAS 撤出周末联机，Mac 画面上 2 秒内播放它离开的动画；工作室那条长连接不受影响。
6. **隔离**：阿杰两台设备的 `deneb status` 里都没有构建服务器。PoC 的借道和伪造来源用例（multi-lan-tech §6.4）在真机上重跑，全部不通；注入接口只放在测试构建里。
7. **设备进出**：周末联机的托盘里有构建服务器。拖进去后，阿杰的 NAS 能 ping 通它；拖回托盘，不通了；点提示条上的"撤销"，又通了。
8. **服务按局域网开放**：构建服务器的"网站"只开给工作室：Mac 打得开，阿杰的设备打不开；再开给周末联机，阿杰也打得开。
9. **谁能用**：在这台电脑上不让阿杰用，阿杰的设备访问 Mac 开放的服务就失败；Mac 画面上阿杰的连线退成点线，第二行写"用不了这台电脑"。再点一下就恢复。
10. **直连断了**：在引擎里模拟 Mac 和构建服务器之间的 UDP 全丢（同 PoC 的 `/block`，不碰防火墙）。连线改走中转，画面上不出现"断开"，状态不闪；恢复后回到直连。
11. **界面回归**：`go test ./...` 全过；演示模式下改造前后的帧逐帧一致；真实模式下把第 2、3、7、9 条各录一遍，按 DESIGN §11 的清单自查，问题清零。
12. **共存**：Mac 的 Clash TUN 全程开着，全程跑 `monitor-coexist.sh`，上网、Clash、Tailscale 都不受影响。

**内核网卡那一轮**：你确认后，Mac 换成内核网卡模式，再跑第 4、6、7、8 条，用普通程序（`curl`、浏览器）不设代理直接访问。

**风险**

- **引擎底座**：Tailscale 的 magicsock 接不上我们的三张表，就退回 PoC 那份，M1 多 1–2 周。
- **拆 `app` 会碰到动效**：原型的动效调得很细，拆业务数据和界面状态时容易带出跳帧。靠演示模式下的逐帧比对兜住，比对通过了才接真实数据。
- **和别的会话撞文件**：根目录的界面文件可能有别的会话在改，挪目录和拆 `app` 之前先对齐。
- **真实数据比演示数据乱**：设备名更长、设备更多、状态变得更勤。M1 先处理名字截断和防抖；设备多到画布放不下的情况记下来，M2 设计。
- **邀请链接**：自定义链接 `deneb://` 要装好的应用才认，开发时用 `mygo dev` 跑的应用可能收不到。退路是把链接粘到命令行里 `deneb lan join <链接>`。
- **热点下打不了洞**：Mac 接手机热点时，到 Windows 只能经中转（multi-lan-tech §6.1），"直接连上"只在部分设备之间看得到。不影响验收，记录里写明当时的网络。
- **Windows 传文件慢**：PoC 的压缩包是 4.8 MB，正式引擎估计 5–10 MB，传一次 5–10 分钟。引擎和命令行是同一个文件，尽量少传。
- **服务器上的已有服务**：Docker 限制 CPU 和内存，只用高位端口，用宿主网络模式；hk-spare 上的 derper 只当客户端用。

### M2 · 局域网模式做完整

**做到什么程度**

- **场景 1、3、5 全部由真实事件驱动**：先经中转连上，打通后换直连；"网络变了，改走中转"；有人加入时，小球和设备依次弹出；关掉一项服务时，正在用它的那条线里跑一小段红光（场景 5）。红光要知道"谁正在用我的哪项服务"，由引擎从过滤层的连接记录里报给界面。
- **场景 3**：侧边栏里局域网的开关（暂停）；"全部"视图，几块区域在同一张画布上；悬停聚焦；设备在区域之间挪；收到邀请的卡片；dev-db 那样的"已连接"计时。
- 把人的小球拖到局域网上就是邀请（DESIGN §6.4）。
- **调研 §6.4 里 demo 还没画的状态**：待同意（虚线球，点一下同意）、需要重新登录（快到期时设备块上有提示，点一下续上）、连不上的原因句（对方离线 / 登录过期 / 被限制 / 路由器不让直连，各配一个能点的动作）、同名设备怎么区分、和 Clash 一类 TUN 模式共存的提示。这些先补进 DESIGN.md、出 demo，你看过再写进客户端（DESIGN §11 的流程）。
- **macOS 菜单栏**：图标表示整体状态，点开是一个自绘面板，里面有我的局域网和开关、共享给我、打开窗口。面板也先出设计。
- **引擎**：只在有流量时心跳；按丢包率和延迟选路；对端常驻在不同中转站时也能转发，为 M4 打底。
- 设备改名、改种类。

**怎么验收**

- 还是 M1 的四台真机，另加三项：
  - **换网和睡眠**：Mac 换一次网络、合盖睡 10 分钟再打开，30 秒内所有连线恢复，期间不出现错误状态。这一步要你动手，我不去切你的网络。
  - **坏线路**：在引擎里对一个对端丢 20% 的 UDP（重现 multi-lan-tech §6.8 的情况），10 秒内改走中转，TCP 流不卡死。
  - **暂停**：暂停周末联机 10 秒，工作室的长连接零影响，恢复后 0.5 秒内通（PoC 的测法）。
- **待同意**："新设备要同意"默认开着（§0.2），我把构建服务器拖进周末联机，阿杰的画面上出现虚线球；他点一下，构建服务器才连得进来；他拒绝，就连不进来。
- 每个新画面录浅色、深色各一遍，按 DESIGN §11 自查清零。

**风险**

- 新状态的设计还没做，设计和评审要占时间，客户端部分可能要到 M2 后半段才开始写。
- "全部"视图里设备和区域一多，布局（区域伸缩、连线避让）比单个局域网复杂一截。
- 只在有流量时心跳会让第一个包慢一点，要和省电权衡。用 M1 的启动测试守住：首包经中转 0.2 秒内应答。

### M3 · 设备共享模式和 Web

**做到什么程度**

- **控制服务器**：分享（一台设备 × 一个人，带开放哪些服务）和公共设备（属于局域网，不属于个人，见 0.2）。网络图里加"分享"这种范围：接收人的设备只看得到这一台；过滤只放行接收人连过去，反过来不行。分享出去的设备走分享方的中转站，分享方没有自己的就走公共的；分享方的中转站只服务这台设备和接收人之间这一条（定价文档 §2.3）。M3 时还只有一个中转站，这条规则在 M4 有了多个中转站后再验一次。
- **位置的限制**：两种模式都齐了，照定价文档 §1.4 开始限制，满额的画面照 §1.5 做：平时不显示数字；只剩 2 个时"+"下面写"还能加 2 人"；满了"+"变成虚线圈，点开能腾位置；拖进来放不下就在边上停住，不摇晃、不弹框；已经在名单里的人不受影响。"加位置"这个按钮先放着，付费在 M7。
- **桌面客户端**：侧边栏的"共享给我"真实可用；设备卡片写清"只有他能连你，反过来不行"；把设备拖到人的小球上就是分享，能撤销。
- **Web 后台**：场景 4 的画面和交互：设备格子拖到成员行上就分享；成员拖到设备上也是分享；点成员行展开他已有的设备，点 × 收回。
- **Web 客户端**：登录、接受邀请、看局域网和设备、拖进拖出、服务开关、谁能用、分享、下载客户端。Web 上没有"这台电脑"，画面怎么画先出设计（§5）。

**怎么验收**

- 我在浏览器的后台把构建服务器分享给阿杰：阿杰 Windows 上的 `deneb status` 里出现它，能打开它开放给阿杰的服务；阿杰看不到工作室里别的设备；构建服务器连不了阿杰的设备。收回后 2 秒内不通。
- 在浏览器里把场景 4 录屏，按 DESIGN §11 自查清零。
- 没装客户端的人在浏览器里打开邀请链接，也能接受邀请，并被引导去下载客户端。
- 位置：测试部署里把额度临时调成 3 人，再加两个测试账号。我分享构建服务器给阿杰，再邀请第三个账号进工作室，他接受后我的位置满了（我、阿杰、他），"+"变成虚线圈；把设备拖给第四个账号，放不进去；收回分给阿杰的设备，提示条可撤销，能撤销的 4 秒里位置先留着（定价文档 §1.5 第 7 条），之后才能加新人。全程已经在名单里的人照常连接。
- WebAssembly 的体积和首屏时间达到 §2.5 的线。

**风险**

- MyGo 在浏览器里的表现（体积、首屏、输入法、屏幕阅读器）在这个项目里还没验证过。第一周先量，不达标就换 TypeScript，M3 多 2 周。
- 分享的范围和"谁能用"叠在一起，权限组合变多，网络图计算的属性测试要跟着加。
- 如果 0.2 里场景 4 的"管理员"定为整个服务的管理员，Web 后台要多一层运营后台。

### M4 · 中转站

**做到什么程度**

照定价文档的丙：公共的兜底，自己的拖进来。

- **多个中转站**：一个局域网可以用几个；每台设备选一个常驻；发给对端时走对方常驻的那个（multi-lan-tech §3.6，原型没测过）。
- **公共中转站**：我们出钱，所有登录了 Deneb 的设备都能用，不限流量，只限每条连接的速度，限多少写在中转站卡片的"更多"里，不悄悄限。第一阶段放香港、东京这类离大陆近、线路好的机房，不在大陆放。
- **我的服务器**：Deneb 提供一个中转站镜像，装在自己的服务器上就带准入（§2.6.3）。主人把它拖进自己的局域网，它只服务这些局域网和主人分享出去的设备；流量算主人的，不计入任何额度；卡片上写"这个月替周末联机转了多少"。
- **家里的设备当中转站**（场景 2 里"Mia 的设备"）：引擎要能替别人转发，类似 Tailscale 的 peer relay，手机不能当。工作量大，排在 M4 后半段（粗估另加 3–4 周），也可以挪到公测以后。
- **场景 2**：托盘里的中转站拖到两台连不上的设备之间就加进来，拖回托盘就移除，点一下它会自己飞到推荐位置，都能撤销。中转站对整个局域网生效，画面只是把它画在需要它的那条线上。
- **选哪个**：有自带的就先走自带的（不限速，也不花公共的钱）；自带的连不上时自动改走公共的，胶囊写"改走公共中转站"，不出现"断开"（同场景 1 的"网络变了"）。
- **中转站能看到什么，写在卡片上**：朋友的中转站写"内容全程加密，Mia 看不到；Mia 能看到谁在经它连、用了多少"（定价文档 §2.4）。
- 卡片的"更多"里写经哪个中转站、延迟多少、限速多少。

**怎么验收**

- hk-155 上跑一个 Deneb 自己的中转站扮演"公共（香港）"，hk-spare 上跑一个扮演"我的服务器"。都在 Docker 里、用高位端口，不碰现成的 derper。让 Mac 常驻其中一个、Windows 常驻另一个，两边照样连得上。
- 在引擎里封掉 Mac 和 Windows 之间的 UDP，画面上出现"经香港中转"（公共的兜底）；把"我的服务器"拖进来，改走它；停掉它，10 秒内改走公共的，画面不出现"断开"；拖回托盘就移除，能撤销。
- 准入：不在那几个局域网里的设备，以及没登录 Deneb 的 DERP 客户端，连"我的服务器"都被拒绝；公共的只拒绝没登录 Deneb 的。
- 限速：经公共的下载，速度封在设定值；经"我的服务器"不限。
- 用量：跑一天后，控制服务器里有每台设备经各个中转站的总量，没有"谁和谁"的记录。
- 卡片上的新画面（来源、能看到什么、用量）录浅色、深色各一遍，按 DESIGN §11 自查清零。

**风险**

- 公共中转站要买机房、定限速，一个月花多少还没测算（定价文档 §3 第 1 条）；大陆放不放要等法务（§3 第 2 条）。M4 的验收先用 hk-155 扮演公共的，不等采购。
- 准入接口连不上时，derper 默认放行（`--verify-client-url-fail-open` 默认开着）。公共的可以放行；自带的要关掉，代价是控制服务器宕机时新的中转连接进不来，已经连着的不受影响。
- 家里的设备当中转站要在引擎里实现转发，还要处理家用网络的上传带宽，工作量大，可能单独排。
- 中转站的线路质量决定"经中转"好不好用：PoC 里 hk-spare 的中转延迟在 300–650ms 之间波动，公共中转站的选址要实测。
- Deneb 自己的中转站也要证书。和控制服务器一样，先用自签证书加固定指纹，正式版换域名证书。

### M5 · Windows 和 Linux 完整客户端

**做到什么程度**

- **Windows**：Wintun 内核网卡、按对端 `/32` 的路由、只接管 `deneb.internal` 的 NRPT 规则、Windows 服务、通知区托盘和窗口、绑物理网卡（IP_UNICAST_IF）。
- **Linux**：tun 网卡、按对端 `/32` 的路由、systemd-resolved 的 `~deneb.internal`（没有就退回用户态）、systemd 服务、AppIndicator 托盘和窗口；服务器另出一个只含引擎和命令行的包。机器开着 IP 转发时（装了 Docker 的 Linux 默认开着），出口那一关要拦住借道的包（multi-lan-tech §7 第 3 条）。
- 界面上只有窗口按钮的位置不同（DESIGN §8）。

**怎么验收**

- **Windows 测试机**：先空跑检查（照 PoC 的 `-preflight`），你确认后再装内核网卡。全程监控测试机上的 Tailscale 和上网，因为我们就是经 Tailscale 连它的，断了就连不回去。在 Windows 上照 M1 的第 4、6、7、8 条跑一遍，用普通程序不设代理直接访问；撤销后，路由表和 NRPT 与开始前一致。
- **Linux**：内核转发和过滤在 colima 的容器里测；桌面在 VMware Fusion 里装一个 Linux 虚拟机，测托盘和窗口（要下载系统镜像，先问你）。
- 三个平台的界面截图逐张比对，除了窗口按钮都一致。

**风险**

- Windows 测试机经 Tailscale 连接，装网卡、改 NRPT 出了问题就会连不回去。照 PoC 在 Mac 上的做法：只在开始和结束各改一次，全程监控，备好撤销脚本。
- 没有 Linux 桌面测试机，桌面版的验收要等虚拟机。
- Linux 发行版差异大（有没有 systemd-resolved，用 nftables 还是 iptables），先只保证 Debian 和 Ubuntu。

### M6 · 普通人装得上

**做到什么程度**

- **macOS**：定下网卡用网络扩展还是特权守护进程。网络扩展要 Apple 开发者账号和网络扩展授权，用户要在系统设置里批准一次；特权守护进程在安装时要一次管理员密码。然后签名、公证。
- **Windows、Linux**：安装包、开机启动；卸载要干净，网卡、路由、DNS 设置全部撤掉。
- **自动更新**：用 MyGo 的更新器，引擎跟着界面一起更新。
- **首次打开的引导**：登录（换成正式的登录方式，见 0.2）、装网卡（要权限时说一句为什么）、加进第一个局域网。
- **和代理软件共存**：检测到 Clash、Surge、v2rayN 一类软件时，用一句话提示，不去改它们的配置（multi-lan-tech §3.7）。
- **诊断**：卡片的"更多"里能导出一份诊断包，不含密钥，也不含流量内容。

**怎么验收**

- 三个平台各用一个干净系统（虚拟机），从下载开始装，到连上第一个局域网，全程不打开终端。
- 卸载后，路由表、DNS 配置、网卡列表都和安装前一致。

**风险**

- Apple 的网络扩展授权和公证要排队，最好在 M4 时就开始申请。
- 装系统服务和网卡驱动不在 MyGo 默认的打包能力里，安装步骤要自己写。

### M7 · 公测

**做到什么程度**

- **加位置的付费**：超出 6 人以后的价格另一次定，建议只为多出来的人付钱（定价文档 §3 第 5 条）。
- **地址池扩容**：一个部署的 `/16` 约 6.5 万台设备，我们自己运营的公共服务会超过。公测前在"以 IPv6 为主"和"给对端另编本机地址"之间选一个（multi-lan-tech §3.3、§7）。
- **控制服务器**：高可用、备份和恢复演练、监控告警；正式域名和证书。
- **安全**：过滤代码的模糊测试（IP 分片、IPv6 扩展头、ICMP 错误报文）、网络图计算的属性测试、外部安全审查；隐私说明。

**怎么验收**：找一批外部测试用户（你来定人），跑两周，看连上率、直连率、经中转的延迟、崩溃和反馈。

**风险**：部署地点、合规和成本都取决于 0.1 第 2–4 条和 0.2 的运营方式。

## 4. 测试机怎么用

| 机器 | 角色 | 规矩 |
| --- | --- | --- |
| 本机 Mac | 开发机；macOS 客户端；"这台电脑" | 上网、Clash、Tailscale 不能受影响；建网卡、加路由、写 DNS 前先确认；测试期间全程跑 `monitor-coexist.sh`；地址不用 `100.64/10` 和 `198.18/15` |
| colima（本机的 Docker） | 每次改动都跑的集成拓扑：控制服务器、几个用户态节点、derper，用 Docker 网络模拟 NAT | 只在容器里，不碰本机网络 |
| hk-155 | 控制服务器；我的 Linux 节点；M4 起一个 Deneb 自己的中转站 | 只用 Docker 和高位端口（80、443、3478/udp、41641/udp 已被占）；不碰宿主网络、防火墙和已有服务 |
| hk-spare | 中转站（你现成的 derper，只当客户端用）；阿杰的 Linux 节点；M4 起一个 Deneb 自己的中转站 | 同上；现成的 derper 不改配置，不加重负载 |
| Windows 测试机 | 阿杰的设备；M5 的 Windows 客户端 | 经 Tailscale 连，改网络配置先确认；传文件前先压缩；进程用完用 `taskkill` 停掉 |
| VMware Fusion | M5、M6 的 Linux 桌面和干净系统 | 下载系统镜像前先问你 |

测试分四层：

1. **单元测试**：过滤、名字、地址分配、网络图计算（属性测试）、对账和防抖。
2. **界面测试**：MyGo 的 `ui.NewTester` 无窗口测试；用 `TestFrames` 出帧；DESIGN §11 的录屏自查。
3. **集成测试**：colima 里的多节点拓扑，含 PoC 的攻击用例。
4. **真机验收**：每个里程碑末尾跑一次，脚本放在 `scripts/` 下，沿用 `poc/multi-lan/scripts/` 的写法。

按全局规则，本地只跑受影响的测试，完整 CI 交给远端（仓库建好以后）。
