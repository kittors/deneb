- 界面原型挪到了 `cmd/deneb/`，`go tool mygo dev ./cmd/deneb` 能跑。
- `app` 已拆开：业务数据来自 `client.Store`；演示数据在 `client.Demo`，实时数据在 `client.Live`（对着引擎的本机接口）。
- 演示模式下，改造前后的帧逐帧一致：深浅色各 25 帧，每帧差异都在渲染噪声以内，见下文"逐帧一致"。
- 实时模式下，验收第 2、3、7、9 条已在假拓扑里自动走通，另外加测了第 1、5 条。`client.Live` 也对着真引擎加开发模式控制服务器跑通了：登录、新建局域网、邀请、预览、首次开放本机服务。

## 做了什么

### 1. 挪目录

- 根目录的 `*.go`（含 4 个测试文件）和 `mygo.json` 挪到 `cmd/deneb/`。
- `.gitignore` 加了两行：`/cmd/deneb/build/`、`/cmd/deneb/.mygo/`。
- 根目录的 `deneb`、`deneb.test` 是旧的编译产物，没删，本来就在 `.gitignore` 里。
- `mygo.json` 加了 `"urlSchemes": ["deneb"]`。开发版应用的 Info.plist 已经声明了 `deneb` 协议。

### 2. 拆 `app`（计划 §2.7）

- **`client/model`**：只读快照 `Snapshot`，整份替换、从不原地修改，里面没有 MyGo 类型，主人色存编号。快照包括人、局域网、设备、服务、路径、中转站、本机服务 `Local`；另有 `Op`、`Result`、`Invite`、`Error`。
  - `Snapshot.With(op)` 是乐观叠层：只复制被改动的部分；已经生效的操作再叠一次不变。
  - `ColorFor`：我是蓝色，别人按 id 固定分到另外五种颜色之一，所以在我所有局域网里同一个人颜色相同。
- **`client.Store`**：`Snapshot`、`Subscribe`、`Do`、`Login`、`Open`、`Preview`。比计划多了后三个，因为登录、"打开"、邀请预览不是控制服务器的操作。`Do` 返回 `Result`（版本号，加上新局域网或邀请链接），不只是版本号。
- **`client.Demo`**：原型 `newApp()` 的全部数据，设备 id 保持原型的（`mac`、`mia`、`jdesk`……），因为光束周期和连线弯曲按 id 算。另外有一个模拟器 `Simulate`：`leave`、`network`、`connect`/`connected`、`offline`。
- **`cmd/deneb`**：
  - `device` 拆成 `facts`（快照的事实，每来一份快照就刷新）和界面那一半（位置、拖拽、动画）。快照里已经没有的设备保留最后的样子，所以飞走时文字不变。
  - 每帧开头 `sync`：取 store 的快照，叠上没确认的操作，再 `reconcile` 对账。
  - 对账的规则：
    - 别处加入的设备：在原处或空位弹出，轨道从这台电脑长出；
    - 别处撤出的：原地缩小淡出，轨道收回；
    - 我的设备在别处被移进移出，或者操作被拒绝：飞回去；
    - 路径变了：重画这条连线。
  - 操作先动画、后确认（`send`）。被拒绝就把叠层撤掉，东西退回原处，提示条说服务器给的那句原因。
  - 摆放按"局域网 × 设备"记在本机 `~/Library/Application Support/Deneb/layout.json`，一秒最多写一次，写盘不在主线程；演示模式只放在内存里。

### 3. `liveStore` 和界面的真实功能

- **`client.Live`**：
  - 盯 `/v1/watch`。把用户视图（`proto.UserView`）和引擎的状态合成快照；
  - 路径经过防抖；
  - 每 30 秒查一次 `/v1/services`；
  - 引擎不在时每秒重试。
  - `Do` 遇到"引擎没在运行"会用同一个幂等键重试两次。
  - 引擎给的错误句子去掉结尾句号，直接放进提示条。
- **`client/fakeworld`**：假的控制服务器加 M1 验收拓扑（kittors 的这台电脑和构建服务器，阿杰的台式机和 NAS），驱动引擎线的 `fake.Engine`。
  - 判断操作的规则和控制服务器一样：只有主人能挪设备，只有拥有者能邀请。
  - 新连上的设备先经中转、再换直连，和 PoC 启动测试一样（0.12 秒、0.63 秒）。
  - 提供 `Fresh`（还没登录）和 `Ready`（拓扑的终态）两种起点。
- **界面**（M1 的"做到什么程度"）：
  - 侧边栏列出我的局域网，点一下切换画布，切换只换画面。测试里来回切 10 次，版本号不变。
  - "新建局域网"就地变成输入框：回车或点别处就新建（这台电脑跟着进去），Esc 取消。
  - 托盘拖进、拖出、撤销，卡片里的"移出这个局域网"，都发真实操作。
  - 卡片里的服务开关、"谁能用"发真实操作。这台电脑的卡片还会列出本机在听、还没开放的服务，开关一开就首次开放。
  - "打开"：先调 `/v1/open`，再交给系统打开（屏幕共享用 `vnc://`，远程桌面用 `rdp://`，共享文件夹 `smb://`，命令行 `ssh://`，网页 `http(s)://`）。
  - "邀请朋友"复制链接，提示条说"邀请链接已复制，发给朋友就行"。
  - 打开 `deneb://join/<令牌>` 会先预览，再弹出"阿杰邀请你加入「周末联机」"（样式照 `design/demos/v3` 的 `.invite`）。点"加入"后，侧边栏的新行展开并亮一下，画布切过去，设备依次弹出，轨道长出。登录前打开的链接等登录完再弹。
  - 首次打开只有星标和"登录"按钮；登录在浏览器里完成，等待时按钮下面一行小字。
  - 引擎没应答时显示"正在连接 Deneb…"。用户态下由界面启动引擎（引擎线的 `EnsureRunning`）；环境里没设 `DENEB_CONTROL` 时，给 M1 在 hk-155 的地址和指纹。
  - 没有局域网时，画布上只有一句怎么新建、怎么加入。
- **连线新增的状态**（DESIGN §3.4、§3.5、场景 1）：
  - 正在连接：缓慢流动的灰色点线；
  - 连不上、不在线：静止的虚线；
  - 不在线时设备块 300ms 渐变成灰，图形半透明；
  - 从等待变成连上：点线留在长出的轨道下面，轨道接上后才淡出；
  - 直连和经中转互换：旧路线的光先停，轨道淡出，同时新路线长出；
  - 中转站在第一条经中转的连线出现时弹出，最后一条离开时缩小淡出。

### 4. 真实数据的毛刺

- **名字截断**：
  - 画布上的设备名最宽 128（就是设备占地的宽度）；
  - 卡片里 186，标题区的局域网名 420，侧边栏行内；
  - "谁能用"里的人名 96；
  - 提示条里的名字最多约 12 个汉字，超出用"…"（`short`）。
- **防抖**（§2.7 第 7 条，只在 `client` 里做、只在那里测）：
  - 新连上的设备，前 2 秒只显示"正在连接…"。这 2 秒从引擎报告的连接起点 `Since` 算起，所以打开窗口时早已连上的设备直接显示。
  - 直连和经中转之间的变化要持续 2 秒才换画面。
  - 已连上的设备完全连不上（正在连接、连不上、不在线）要持续 6 秒才显示。直连断后约 2.4 秒才换到中转（multi-lan-tech §6.2），这期间画面不出现"断开"。
  - 人做的事（拒绝、暂停）立即显示。

## 逐帧一致（演示模式）

- **基线**：改造前用原型代码跑 `TestFrames` 拍的 50 帧。原型代码已经改了，又没有 git 提交，这份基线是唯一的"改造前"，**别删**。存了两份，内容相同：
  - 仓库里：`design/plan/m1/client-frames-baseline/`（和本文件同目录）。已写进 `.gitignore`，免得 17 MB 的图片被误提交；要不要放进仓库，等提交时再定。注意 `git clean -X` 会删掉它。
  - 共享笔记目录：`~/Library/Application Support/Claude/side-session-notes/local_95d3e1c1-49b1-4ecd-adc1-4ad13ff2dab6/client-frames-baseline/`。
  - 每份都有 50 张 PNG 和一个 `SHA256SUMS`。清单本身的 sha256 是 `ec7468689c58cf724aa3b213134ce9a99aca20b9d43f2834dca7e4f7c2264879`；在目录里跑 `shasum -a 256 -c SHA256SUMS` 能逐张核对。
- **噪声**：同一份原型代码连拍 4 次（多核 2 次、单核 2 次），帧之间本来就有差异：每帧最多 14 个像素，每个像素最多差 1/255。来源是 MyGo 软件光栅化内部的缓存，单核也去不掉，改不了。
- **判定**：`TestFrames` 加了 `DENEB_BASELINE`，每帧差异超过 64 个像素、或者任何像素差超过 1，就判失败。挪个位置、改个颜色或大小，都会让几百个像素的差值大于 1。
- **结果**：每次改动后都重跑了，最后一次全部通过。和第一套基线比，48 帧逐字节相同，另外 2 帧（tray-joining）各差 3 到 5 个像素、每像素差 1/255，那正是基线自比时出噪声的帧。
- **复跑**：

```bash
mkdir -p /tmp/frames && DENEB_FRAMES=/tmp/frames DENEB_BASELINE=$PWD/design/plan/m1/client-frames-baseline go test -run 'TestFrames$' ./cmd/deneb
```

在仓库根目录执行。`go test` 是在 `cmd/deneb` 里跑的，所以基线必须写绝对路径（上面用 `$PWD`），写相对路径会找不到文件。帧目录要先建好。第 11 条自查修了提示条从托盘后面升上来的问题，有 3 个镜头（深浅色共 6 帧）是有意改的，`TestFrames` 里列为有意改动，不再拿基线比；其余 44 帧照比，最后一次复跑全过。

## 怎么跑

```bash
DENEB_DEMO=1 go tool mygo dev ./cmd/deneb      # 演示（现在后台开着的开发窗口就是这个）
```

演示模式和假世界里，⌥⌘1 到 ⌥⌘5 模拟外部事件：
1. 阿杰撤出 NAS，再按一次加回；
2. 网络变了（直连和经中转互换）；
3. 收到邀请；

`mygo dev` 不传命令行参数，所以用环境变量；`deneb --demo` 也行。开发时对着真引擎，请把 `DENEB_SOCKET`、`DENEB_STATE_DIR` 设到临时目录，别碰默认的那份。

## 自查（DESIGN §11）

§11 的录屏工具是给 HTML 设计稿用的，原生客户端拿不到逐元素的 `trace.json`。我改成：用测试器录 60fps 连续帧拼联系表逐帧看，规则照 `motion-check.mjs`（瞬移、急停、闪烁、一帧尺寸跳变）。自查找到并修掉了这些：

1. 原地缩走或弹出时，连线端点的光点先于设备出现、晚于设备消失，而且是一下子没的。改成随轨道淡入淡出。
2. 从等待变成连上、或者直连和中转互换时，中间有约 200ms 一条线都没有。改成旧线留着淡出。
3. 设备离线时一帧内变灰，改成 300ms 渐变。
4. 中转站在最后一条连线离开时一下子消失，改成缩小淡出。
5. 托盘里最后一台设备拖出后，托盘退场和提示条重叠。改成托盘退完提示条再落下。
6. 打开窗口时，所有已连上的设备都会先显示 2 秒"正在连接…"再重长轨道。改成防抖窗口从引擎的 `Since` 算。
7. 设备缩走中又被加回时，会生成同 key 的两个元素。改成让它原地长回来。
8. 指针停着不动时，提示条照样到时消失，不合 DESIGN 的"指针停在上面时不消失"。这是第 7 条在假世界冒烟时发现的。原因：只有重建界面时才看指针在不在上面，指针不动就没有重建；指针来时离到期还超过 1.5 秒的话，到期那次重建就先把它收了。改成指针在上面时每秒再看一次（`panels.go`），回归测试 `TestToastStaysUnderARestingPointer`。
9–12. 真实模式录帧自查又找出 4 处：这台电脑不在的局域网里写"正在连接…"、第一张邀请卡片没有入场、提示条从托盘后面升上来、中转站比旧连线先消失。见"第 11 条：真实模式录帧自查"一节。

## 还差什么

- **真机验收**由主会话协调。客户端这边要用到的：Mac 上默认路径的引擎（界面会自己启动），控制服务器 hk-155。
- **`deneb://` 链接**：开发版应用已经声明了协议，但我没在你正看着的窗口里实际 `open` 过，怕弹卡片打扰。第 3 条真机验收时验证；收不到的退路是 `deneb lan join <链接>`（计划风险里写过）。
- **"打开"没在真机上点过**：Mac 上 `rdp://` 要装微软的 Windows App；`smb://` 带端口号（用户态是 `127.0.0.1:随机端口`）Finder 认不认要实测。
- **我自己的设备没有"打开"**（M2 设计问题，主会话已记进 `m1-acceptance.md`）：M1 第 8 条改由命令行经 SOCKS 验证。
- **引擎线（已修）**：`/v1/services` 曾把 macOS 的"隔空播放接收器"（5000 端口）当成网站，引擎线已改成按种类认，例如网站要真回 HTTP、而且不是隔空播放。
- **只画一个中转站**：画布只有一个中转站的位置，多个中转站在 M4。几台设备都经中转时路线会绕，那是原型的画法。
- **画布放不下**：设备多到放不下的情况记下来了，M2 设计（计划风险）。
- **演示和假世界的代码在正式二进制里**：`cmd/deneb` 会编译进 `client/fakeworld` 和引擎的 `fake`，只有设了 `DENEB_FAKE` 才用。M6 打包时用构建标签去掉。
- **M1 不做的**照计划：场景 3 的"全部"视图和局域网开关、暂停、待同意、登录到期、菜单栏、改名。
