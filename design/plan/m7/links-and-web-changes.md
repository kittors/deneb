## 1. 连线上的光（桌面）

### 1.1 现在的样子

- 每条线上有 4 束光，两个方向各两束，每秒走 150；经中转时，在中转站停 0.2 秒（`cmd/deneb/links.go`）。
- 下面三种情况，都当成"重新连上"处理（`sync.go` 的 `repath`）：
  - 换了线路（直接 ↔ 中转）；
  - 连上了（正在连接 → 直接连上）；
  - 重新上线。
- "重新连上"的样子：新的线从两头长出来，用 0.48 秒；两头各有一个光点，往中间走；线长好以后，换成平常的光。

### 1.2 改前逐帧看到的

| 什么时候 | 哪一帧 | 看到的 |
| --- | --- | --- |
| 换线路 | 变的那一帧 | 旧路上正在走的光一帧没了。旧路的线是慢慢淡掉的，光没有跟着淡 |
| 换线路、连上、重新上线 | 新线长好的那一帧（变化后 0.48 秒） | 两个光点在中间碰头，停几帧，然后一帧没了 |
| 换到经中转（路长） | 同一帧 | 新路上有光直接出现在半路，一出来就是全亮 |
| 下线 | — | 光 0.16 秒淡出，线换成虚线，没问题 |

- 半路冒出来的原因：新的光本该"从两头一起出发"，可第二束的起点是按路长算的。路一长，起点就落在路中间。
- `cut-check.py` 查到的：
  - 设备换线路：浅色 4 处，深色 3 处；
  - 下线又上线：1 处；
  - 正在连接到连上：1 处。
- 这些都是上面几种情况。旧光一帧没了那一下，查到的处数里没有：光本身在动，工具不算硬切，是看逐帧图看出来的。

### 1.3 打算怎么改

改的只有 `links.go` 和 `repath`：

1. 旧路的光不一帧没：换线路时，旧路的光接着在旧路上走，用 0.16 秒（`fadeTime`）淡出，和旧路的线一起走。
2. 光点碰头以后不一帧没：新线长好以后，碰头的光点用 0.16 秒淡出。同时，新的光从两头出发。
3. 新的光都从两头出发：重新连上时，四束光的起点都放在线的两端（藏在设备块下面），一束接一束出来，不会出现在半路。
4. 一次一件事：旧光淡出和新线开始长是同一个时候，但一个在旧路上，一个在新路上，不叠在一起。

验收：

- 录这五种情况，逐帧看光有没有一帧没了、有没有从半路冒出来（后两种是主会话 11-18 加的）：
  - 设备换线路；
  - 设备下线又上线；
  - 正在连接到连上；
  - 局域网暂停和恢复；
  - 切换局域网时，两边都有的那几条线。
- 浅色、深色，窄、中、宽三种窗口都录。
- 改后用 `cut-check` 查，要是 0；标着 look 的，要人看过。

## 2. 网页的内容变化

### 2.1 网页现在怎么更新

服务器推来新的一份数据，页面就重画。重画分两种。

**整块重写（`innerHTML`）**：旧的元素全扔掉，新的一帧换上。没有过渡，鼠标停在上面的悬停效果也一起没了。

- 侧栏（`shell.ts` 的 `side`）：每推来一次数据，整个重写一次。下面这些都一帧变：
  - 计数；
  - 局域网的行、新的邀请；
  - "等同意"、蓝点。
- 设备卡片（`v3-app.ts` 的 `sheet`，同一台设备刷新时）：整张卡片重写。状态、胶囊、服务、名字，变了的都一帧换。
- 页头的头像那排（`setStack`）、共享给我页的头像（`shared.ts`）、中转站页的格子（`relays.ts` 的 `drawMine`、`drawPub`）。

**按元素改**：画布上的设备（`lan.ts`）、托盘、提示条。这些有动画，可细处还有一帧换的：

- 设备下面那句（`setSub`）：新字直接换上再淡入，旧字一帧没。这和第 16 批改之前的页头那句一样。
- 不在线变灰：块的颜色是 CSS 变量，换了不会淡变。
- 虚线框、×、"续上"按钮：一帧出现，一帧没。
- 新设备有时一帧出现在画布边上：落点就在出现的地方，看不到它挪过去。
- 局域网改名：页头标题一帧换（`setTitle` 直接设 `textContent`）。

网页的局域网页上没有连线和光（网页不是一台设备，不在中间），所以 §1 只管桌面。

### 2.2 改前录到的（浅色、深色各一段）

| 录的那一段 | 看到的 |
| --- | --- |
| 新设备上线（局域网页） | 新设备一帧出现在画布右上；侧栏"我的设备"的数 4 一帧变 5；页头那句一次一件事（第 16 批，对的） |
| 新设备上线（我的设备页） | 新卡片一帧出现；侧栏的数一帧变；"添加设备"平滑地挪到下一格，提示条淡入（这两样是对的） |
| 有人共享设备给我 | 侧栏"共享给我"一帧多出计数，这一行一帧变成提醒的底色 |
| 卡片开着时，设备加进局域网 | 卡片里的局域网胶囊、服务、说明一帧全换 |

"有人共享设备给我"那一段，`cut-check` 一处也没查到。那一行主要是颜色变了，亮度变得少，而工具只比灰度。这是看逐帧图看到的。

### 2.3 打算怎么改

用一个办法管所有整块重写的地方：`el.innerHTML = html` 换成 `morph(el, html)`，放在新文件 `web/app/src/morph.ts`。它做的事：

- 把新的 HTML 和现在的元素一一对上：先按 `data-id`、`data-k`、`data-key`，没有的按位置和标签。
- 对上了的元素留着，只改变了的属性和 class。颜色、底色有 CSS 过渡的，自己就淡变。
- 字变了：用 `swapText`，一次一件事（第 16 批的）。
- 新出现的元素：淡入，占的地方从 0 长开，和桌面的 Enter 一样。
- 没了的元素：淡出，占的地方收起，和桌面的 Exit 一样。

这样元素都留着，悬停、焦点、展开的"更多"都不会被重画打断。

事件也要跟着改：

- 现在每次重写完，都重新挂一遍点击事件。换成 morph 以后，留下来的元素不能再挂一次。
- 改成挂在外面那一层，按 `data-id` 分派（事件委托）。

用在这些地方：

1. 侧栏：计数用 `swapText`，行的增减淡入淡出、收起。
2. 设备卡片的刷新：状态、胶囊、服务。
3. 页头：标题用 `swapText`，头像那排的球增减时淡入淡出。
4. 画布上的设备：
   - 下面那句（`setSub`）改成 `swapText`；
   - 不在线变灰：颜色淡变（`@property` 注册颜色变量）；
   - 虚线框、×、续上按钮：淡入淡出；
   - 新设备出现：淡入。
5. 共享给我页、中转站页、我的设备的卡片网格。

这一批不做运营后台（`console.ts`、`operate.ts`）：引擎线正在改 `operate.ts`，等它合进来再做。

### 2.4 和引擎线不碰同一个文件

引擎线的 worktree（`stun-console`）改了这些文件：

- `web/app/src/model.ts`、`operate.ts`、`relays.css`；
- `cmd/deneb-web/mock.go`、`web/probe/record-web.mjs`；
- 另外加了 `stun*` 几个新文件。

这一批这样避开：

- 上面这几个文件都不碰。
- 录屏要用的变化不改 `mock.go`：
  - 网页的录屏场景先用现在就有的测试接口（新设备上线、有人共享）；
  - 设备下线、换线路要在模拟服务器里加接口，等引擎线合进来以后再加，或者请主会话定先后。
- `web/app/dist/app.css` 是构建出来的，两边都会改到。后合进来的一方重新构建一次。

## 3. 分几步做

1. 连线上的光（桌面）。
2. 网页：`morph` 本身，用在侧栏、设备卡片、页头、设备下面那句。

每一步：

- 录改前、改后，浅色、深色，逐帧看。
- 网页的录屏改用页面自己的虚拟时钟（`record-web.mjs` 那一套），要在 `lan.ts` 等页面的录屏场景表里各加一行。
- 这次的改前是用临时脚本按 screencast 录的：时间是真实的，不是虚拟时钟。

## 4. 顺带要改的工具

`cut-check.py` 只比灰度，只变颜色、不怎么变亮度的（比如共享给我那一行）查不出来。要改成按颜色比。

## 5. 用户定的（11-18，都按推荐）
