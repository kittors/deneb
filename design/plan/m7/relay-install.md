# 用自己的服务器当中转站：安装重做（设计稿）

> 主会话，2026-11-15；用户当天看过，第 8 节七件都按推荐。起因：用户问"添加中转站竟然依赖 Docker，没有 Docker 怎么办，有没有检查公网 IP"，要求依赖尽量少、安装不复杂、把复杂情况都想到。按 AGENTS.md §1，这一稿给用户看过、点头再动手。

## 1. 现在的问题

在"用我自己的服务器当中转站"里点一下，会给出一行 `docker run … deneb-relay:v0 --join <加入码>`。中转站拿加入码向控制服务器报到，之后每分钟同步一次，同步上就算"在线"。

| 问题 | 后果 |
| --- | --- |
| 镜像 `deneb-relay:v0` 从没发布过，我们自己的中转站是在服务器上现场打的 | 别人照着跑，必然失败："找不到镜像" |
| 只有 Docker 一条路 | 没装 Docker 的服务器一步也走不了；国内服务器常常拉不动 Docker Hub；跑 Docker 要 root 或 docker 组 |
| 不查公网地址：没写地址时，把报到请求的来源当成中转站地址 | 家里路由器后面、运营商大 NAT 后面的机器，记下的地址从外面连不进来 |
| 不查端口：设备要用 TCP 47445 和 UDP 47478 | 云服务器安全组、系统防火墙默认挡着 |
| "在线"只说明中转站能连出去，不说明设备能连进来 | 界面显示在线，谁都用不上；设备悄悄绕开，用户不知道为什么 |
| 端口被占、架构不对、加入码过期（1 小时），都没有说法 | 容器反复重启，命令"成功"了却没用 |
| 没有升级和卸载的办法 | 装上就只能一直是这一版 |

## 2. 目标

- **依赖最少**：服务器上只要有 `curl` 或 `wget` 其中一个，几乎所有 Linux 都有。不要 Docker，不要 Python，不要 bash，BusyBox 的 `sh` 也能跑。
- **一行命令，跑完就知道结果**：成功了说成功；没成功说卡在哪一步、怎么办。
- **装上的保证能用**：从外面真正连得上，才在 Deneb 里显示"可以用"。
- **以后不用管**：开机自启、出错自动重启、跟着发版自动更新；卸载一行命令。

## 3. 用户看到的流程

1. Deneb 里点"用我自己的服务器当中转站"。卡片上一句前提："需要一台能从外网访问的 Linux 服务器"，细节放在悬停提示里。下面一行命令，加一个"复制"：

   ```sh
   curl -fsSL https://deneb.app/relay | sh -s -- <加入码>
   ```

   没有 `curl` 的，换成 `wget -qO- https://deneb.app/relay | sh -s -- <加入码>`，折叠在"没有 curl？"里。
2. 在服务器上粘贴运行。终端里一步一行，最后给结论：

   ```text
   ✓ 系统：Linux arm64
   ✓ 已下载 deneb-relay 0.1.9（校验通过）
   ✓ 已安装为系统服务，开机自启
   ✓ 已向 Deneb 报到：中转站"东京"
   ✗ 从外网连不上 TCP 47445
     请在云服务商的安全组里放行：TCP 47445、UDP 47478
     放行后不用重装，Deneb 每分钟会重新检查
   ```

3. Deneb 里的卡片跟着变：
   - 等待安装
   - 检查中
   - 可以用，或者连不上，后面跟原因和办法

   可以用以后，就能像现在一样拖进局域网。

## 4. 怎么做到"依赖最少"

- **一个文件干所有事**：`deneb-relay` 本来就是不依赖任何库的单个程序，这次让它自己会安装：
  - `deneb-relay install --join <码>`：自检、装成服务、报到；
  - `uninstall`：卸载；
  - `status`：自检；
  - `update`：更新。

  复杂的逻辑都写在 Go 里，比写在 shell 里稳，也能测试。
- **引导脚本只做三件事**，用的是 POSIX sh，BusyBox 也能跑：
  1. 认出 CPU 架构；
  2. 用 `curl` 或 `wget` 下载对应的程序，核对 SHA-256；
  3. 运行 `deneb-relay install`。
- **防下载被调包**：Deneb 给出的命令里带着这一版程序的 SHA-256。网络被劫持，或者服务器缺根证书只能退回明文下载，也能核对。
- **从我们自己的下载站下载**（hk-spare），国内拉得动；GitHub 发布页作为备份。
- **Docker 留作可选**：习惯 Docker 的，折叠里给一条用公开镜像的命令。镜像发布到国内拉得动的地方，支持 amd64、arm64。默认不用它。

## 5. 复杂情况，逐一对照

### 5.1 系统和环境

| 情况 | 怎么办 |
| --- | --- |
| 没有 Docker（大多数） | 默认就不用 Docker |
| 只有 `wget`，或者只有 BusyBox | 引导脚本两种都支持，用 POSIX sh 写 |
| CPU 架构：amd64、arm64、armv7（树莓派 32 位、很多 NAS 和路由器）、386、riscv64 | 每种都出一份程序；不认识的架构，直接说"暂不支持 xxx" |
| musl（Alpine）还是 glibc | 程序是静态编译的，两种都能跑 |
| 有 systemd（大多数） | 装成 systemd 服务：无特权用户运行，限 1 核、256 MB，日志限量 |
| 没有 systemd：Alpine 用 OpenRC，OpenWrt 用 procd，容器和 LXC 里没有 init | OpenRC、procd 各写一份服务；什么 init 都没有时，用 cron 的 `@reboot` 拉起，并说明"重启后自动运行" |
| 没有 root、没有 sudo | 端口都在 1024 以上，不需要 root 也能监听。改用当前用户的服务（systemd --user 加 linger，或 cron），说明"系统防火墙要请管理员放行" |
| `/tmp` 不让执行 | 程序装到 `/usr/local/lib/deneb-relay`；没有 root 时装到 `~/.local` |
| SELinux（RHEL、CentOS） | 放在标准目录，用系统自带的标签；装完自检能不能启动 |
| 系统时间不准（树莓派没有电池时钟） | TLS 会失败。自检比对控制服务器的时间，差太多直接说"系统时间不对" |
| 磁盘太小（路由器） | 先检查剩余空间，不够就说清楚要多少 |
| 访问外网要走代理 | 认 `HTTPS_PROXY` 这类环境变量 |
| 已经装过（重跑命令） | 不重复装：同一个版本就修复，旧版本就升级 |
| 之前用 Docker 装过（我们自己的几台） | 认出旧容器，问一句以后迁过来，沿用原来的数据和身份 |

### 5.2 网络

| 情况 | 结果 | 怎么办 |
| --- | --- | --- |
| 网卡上就有公网 IPv4（一般的 VPS） | 能用 | 直接用 |
| 云服务器 1:1 NAT（阿里云、腾讯云、AWS 这类：网卡上是内网地址，公网地址在外面） | 安全组放行了就能用 | 用控制服务器看到的地址，靠外网探测确认 |
| 云服务器安全组没放行 | 连不上 | 写明要放行的端口和协议，按服务商给一句提示（比如"安全组 → 入方向"） |
| 系统防火墙（ufw、firewalld、iptables、nftables）挡着 | 连不上 | 认出是哪一种，问过一句再放行这两个端口；不同意就打印命令 |
| 家里的机器，在路由器后面 | 默认连不上 | 先试 UPnP / NAT-PMP / PCP 自动映射端口（用依赖里现成的 `tailscale.com/net/portmapper`，引擎现在还没用它）；不行就说"请在路由器上把 TCP 47445、UDP 47478 转发到这台机器" |
| 运营商大 NAT（拿不到公网 IPv4） | 用不了 | 直接说"这台机器没有公网地址，不能当中转站"；有公网 IPv6 的，说明"只有支持 IPv6 的设备能用它" |
| 只有 IPv6 | 部分能用 | 同上，状态写"只支持 IPv6" |
| 两种都有 | 能用 | 两个地址都报，两个都探测 |
| 公网地址会变（家庭宽带） | 能用 | 中转站发现地址变了就重新报，设备那边跟着更新 |
| 端口被别的程序占了 | 起不来 | 自动换一组空闲端口，报给控制服务器；状态里写明用的是哪两个端口 |
| TCP 通、UDP 不通 | 部分能用 | 能转发，但帮不上直连。状态写"能用，UDP 不通"，提示放行 UDP |
| 服务器所在机房挡入站（少数机房挡少见端口） | 连不上 | 外网探测查出来，说明可以换端口重试（有命令） |
| 控制服务器连得上，但国内设备连不上（跨境线路） | 部分能用 | 不只看控制服务器的探测，也看主人在线设备实际连它的结果；有设备连不上就标出来 |

### 5.3 以后

| 情况 | 怎么办 |
| --- | --- |
| 加入码过期 | 命令里直接说"加入码已过期，请在 Deneb 里重新生成"。建议有效期从 1 小时延长到 24 小时，用一次就作废 |
| 同一台服务器加了两次 | 认出是同一台（同一份数据、同一个地址），不重复建，提示"这台已经是中转站'东京'了" |
| 升级 | 默认跟着 Deneb 发版自动更新：程序核对签名后自己替换、重启。也能手动 `deneb-relay update` |
| 卸载 | `curl … | sh -s -- uninstall`：停掉服务，删掉程序和数据，通知控制服务器。Deneb 里点"不用这个中转站"，也会让它停止服务 |
| 重启、崩溃 | 服务开机自启、出错自动重启；连续失败就停下，并在 Deneb 里报"中转站反复出错" |
| 资源 | 限 1 核、256 MB，日志最多 30 MB（和现在 Docker 的设置一样） |
| 隐私 | 日志只记必要的，照 PRIVACY.md；程序用无特权用户运行，数据目录只有它能读 |

## 6. 装上以后，确认真的能用

- **控制服务器主动探测**：中转站报到后，以及以后每 10 分钟、地址变了的时候，控制服务器从外面连它：
  - TCP 端口做一次 TLS 握手，核对证书指纹；
  - UDP 端口发一个 STUN 请求。
- **第二个位置**：再从 hk-spare 探测一次，避免只是控制服务器那条线路的问题。
- **设备的实际结果**：主人在线的设备会报告连没连上它，这比服务器探测更接近真实情况，尤其是跨境线路。
- **状态这样算**：

| 状态 | 条件 | 卡片上写 |
| --- | --- | --- |
| 等待安装 | 给了命令，还没报到 | 安装命令，剩余有效时间 |
| 检查中 | 刚报到，正在探测 | 正在检查能否从外网连接 |
| 可以用 | TCP、UDP 都通 | 可以用 |
| 部分可用 | 只有 TCP 通，或只有 IPv6 | 可以用，后面一行说明哪里不通 |
| 连不上 | TCP 不通 | 原因和办法，加"重新检查" |
| 不在线 | 超过 3 分钟没同步 | 最后在线时间 |

- 状态从"可以用"变成"连不上"时，用 alert 告诉主人，不要等他自己发现。

## 7. 分工（用户点头后）

| 线 | 做什么 |
| --- | --- |
| 引擎线（`cmd/deneb-relay`） | `install / uninstall / status / update` 子命令；自检；各种 init；端口映射；地址变化重报；自动更新 |
| 控制线 | 外网探测、新的状态和原因、加入码有效期、同一台去重、卸载通知、设备连接结果的汇总 |
| 客户端线 | 桌面和网页的卡片、状态、文案。先出原型，录屏截图，用户点头再接 |
| 主会话 | 引导脚本放到下载站；每次发版把中转站程序（各架构）和校验和放上下载站和 GitHub；可选的 Docker 镜像 |

现在已经装上的中转站（我们自己用 Docker 装的几台）不受影响，以后再迁。

## 8. 用户 11-15 定了：都按推荐

1. **默认装法**：引导脚本加单个程序装成系统服务；Docker 留作折叠里的可选项。
2. **没有 root**：支持，改用当前用户的服务，并说明系统防火墙要请管理员放行。
3. **系统防火墙**：问过一句再放行。也可以只打印命令，让用户自己放行。
4. **家里的机器**：自动试 UPnP / NAT-PMP 映射端口。也可以只支持有公网 IP 的服务器。
5. **加入码**：有效期改成 24 小时，用一次就作废。
6. **自动更新**：跟着 Deneb 发版自动更新，核对签名。
7. **架构**：amd64、arm64、armv7 先出；386、riscv64 看需要。
