# 用自己的服务器当中转站：安装重做（设计稿）

> 主会话，2026-11-15；用户当天看过，第 8 节七件都按推荐。起因：用户问"添加中转站竟然依赖 Docker，没有 Docker 怎么办，有没有检查公网 IP"，要求依赖尽量少、安装不复杂、把复杂情况都想到。按 AGENTS.md §1，这一稿给用户看过、点头再动手。

## 1. 现在的问题

在"用我自己的服务器当中转站"里点一下，会给出一行 `docker run … deneb-relay:v0 --join <加入码>`。中转站拿加入码向控制服务器报到，之后每分钟同步一次，同步上就算"在线"。

| 问题 | 后果 |
| --- | --- |
| 镜像 `deneb-relay:v0` 从没发布过，我们自己的中转站是在服务器上现场打的 | 别人照着跑，必然失败："找不到镜像" |
| 只有 Docker 一条路 | 没装 Docker 的服务器一步也走不了；国内服务器常常拉不动 Docker Hub；跑 Docker 要 root 或 docker 组 |
| 不查公网地址：没写地址时，把报到请求的来源当成中转站地址 | 家里路由器后面、运营商大 NAT 后面的机器，记下的地址从外面连不进来 |
| 不查端口：设备要用 TCP 47445 和 UDP 47478 | 云服务器安全组、系统防火墙默认挡着 |
| "在线"只说明中转站能连出去，不说明设备能连进来 | 界面显示在线，谁都用不上；设备悄悄绕开，用户不知道为什么 |
| 端口被占、架构不对、加入码过期（1 小时），都没有说法 | 容器反复重启，命令"成功"了却没用 |
| 没有升级和卸载的办法 | 装上就只能一直是这一版 |

## 2. 目标

- **依赖最少**：服务器上只要有 `curl` 或 `wget` 其中一个，几乎所有 Linux 都有。不要 Docker，不要 Python，不要 bash，BusyBox 的 `sh` 也能跑。
- **一行命令，跑完就知道结果**：成功了说成功；没成功说卡在哪一步、怎么办。
- **装上的保证能用**：从外面真正连得上，才在 Deneb 里显示"可以用"。
- **以后不用管**：开机自启、出错自动重启、跟着发版自动更新；卸载一行命令。

## 3. 用户看到的流程

1. Deneb 里点"用我自己的服务器当中转站"。卡片上一句前提："需要一台能从外网访问的 Linux 服务器"，细节放在悬停提示里。下面一行命令，加一个"复制"：

   ```sh
   curl -fsSL https://deneb.app/relay | sh -s -- <加入码>
   ```

   没有 `curl` 的，换成 `wget -qO- https://deneb.app/relay | sh -s -- <加入码>`，折叠在"没有 curl？"里。
2. 在服务器上粘贴运行。终端里一步一行，最后给结论：

   ```text
   ✓ 系统：Linux arm64
   ✓ 已下载 deneb-relay 0.1.9（校验通过）
   ✓ 已安装为系统服务，开机自启
   ✓ 已向 Deneb 报到：中转站"东京"
   ✗ 从外网连不上 TCP 47445
     请在云服务商的安全组里放行：TCP 47445、UDP 47478
     放行后不用重装，Deneb 每分钟会重新检查
   ```

3. Deneb 里的卡片跟着变：
   - 等待安装
   - 检查中
   - 可以用，或者连不上，后面跟原因和办法

   可以用以后，就能像现在一样拖进局域网。

## 4. 怎么做到"依赖最少"

- **一个文件干所有事**：`deneb-relay` 本来就是不依赖任何库的单个程序，这次让它自己会安装：
  - `deneb-relay install --join <码>`：自检、装成服务、报到；
  - `uninstall`：卸载；
  - `status`：自检；
  - `update`：更新。

  复杂的逻辑都写在 Go 里，比写在 shell 里稳，也能测试。
- **引导脚本只做三件事**，用的是 POSIX sh，BusyBox 也能跑：
  1. 认出 CPU 架构；
  2. 用 `curl` 或 `wget` 下载对应的程序，核对 SHA-256；
  3. 运行 `deneb-relay install`。
- **防下载被调包**：Deneb 给出的命令里带着这一版程序的 SHA-256。网络被劫持，或者服务器缺根证书只能退回明文下载，也能核对。
- **从我们自己的下载站下载**（hk-spare），国内拉得动；GitHub 发布页作为备份。
- **Docker 留作可选**：习惯 Docker 的，折叠里给一条用公开镜像的命令。镜像发布到国内拉得动的地方，支持 amd64、arm64。默认不用它。

## 5. 复杂情况，逐一对照

### 5.1 系统和环境

| 情况 | 怎么办 |
| --- | --- |
| 没有 Docker（大多数） | 默认就不用 Docker |
| 只有 `wget`，或者只有 BusyBox | 引导脚本两种都支持，用 POSIX sh 写 |
| CPU 架构：amd64、arm64、armv7（树莓派 32 位、很多 NAS 和路由器）、386、riscv64 | 每种都出一份程序；不认识的架构，直接说"暂不支持 xxx" |
| musl（Alpine）还是 glibc | 程序是静态编译的，两种都能跑 |
| 有 systemd（大多数） | 装成 systemd 服务：无特权用户运行，限 1 核、256 MB，日志限量 |
| 没有 systemd：Alpine 用 OpenRC，OpenWrt 用 procd，容器和 LXC 里没有 init | OpenRC、procd 各写一份服务；什么 init 都没有时，用 cron 的 `@reboot` 拉起，并说明"重启后自动运行" |
| 没有 root、没有 sudo | 端口都在 1024 以上，不需要 root 也能监听。改用当前用户的服务（systemd --user 加 linger，或 cron），说明"系统防火墙要请管理员放行" |
| `/tmp` 不让执行 | 程序装到 `/usr/local/lib/deneb-relay`；没有 root 时装到 `~/.local` |
| SELinux（RHEL、CentOS） | 放在标准目录，用系统自带的标签；装完自检能不能启动 |
| 系统时间不准（树莓派没有电池时钟） | TLS 会失败。自检比对控制服务器的时间，差太多直接说"系统时间不对" |
| 磁盘太小（路由器） | 先检查剩余空间，不够就说清楚要多少 |
| 访问外网要走代理 | 认 `HTTPS_PROXY` 这类环境变量 |
| 已经装过（重跑命令） | 不重复装：同一个版本就修复，旧版本就升级 |
| 之前用 Docker 装过（我们自己的几台） | 认出旧容器，问一句以后迁过来，沿用原来的数据和身份 |

### 5.2 网络

| 情况 | 结果 | 怎么办 |
| --- | --- | --- |
| 网卡上就有公网 IPv4（一般的 VPS） | 能用 | 直接用 |
| 云服务器 1:1 NAT（阿里云、腾讯云、AWS 这类：网卡上是内网地址，公网地址在外面） | 安全组放行了就能用 | 用控制服务器看到的地址，靠外网探测确认 |
| 云服务器安全组没放行 | 连不上 | 写明要放行的端口和协议，按服务商给一句提示（比如"安全组 → 入方向"） |
| 系统防火墙（ufw、firewalld、iptables、nftables）挡着 | 连不上 | 认出是哪一种，问过一句再放行这两个端口；不同意就打印命令 |
| 家里的机器，在路由器后面 | 默认连不上 | 先试 UPnP / NAT-PMP / PCP 自动映射端口（用依赖里现成的 `tailscale.com/net/portmapper`，引擎现在还没用它）；不行就说"请在路由器上把 TCP 47445、UDP 47478 转发到这台机器" |
| 运营商大 NAT（拿不到公网 IPv4） | 用不了 | 直接说"这台机器没有公网地址，不能当中转站"；有公网 IPv6 的，说明"只有支持 IPv6 的设备能用它" |
| 只有 IPv6 | 部分能用 | 同上，状态写"只支持 IPv6" |
| 两种都有 | 能用 | 两个地址都报，两个都探测 |
| 公网地址会变（家庭宽带） | 能用 | 中转站发现地址变了就重新报，设备那边跟着更新 |
| 端口被别的程序占了 | 起不来 | 自动换一组空闲端口，报给控制服务器；状态里写明用的是哪两个端口 |
| TCP 通、UDP 不通 | 部分能用 | 能转发，但帮不上直连。状态写"能用，UDP 不通"，提示放行 UDP |
| 服务器所在机房挡入站（少数机房挡少见端口） | 连不上 | 外网探测查出来，说明可以换端口重试（有命令） |
| 控制服务器连得上，但国内设备连不上（跨境线路） | 部分能用 | 不只看控制服务器的探测，也看主人在线设备实际连它的结果；有设备连不上就标出来 |

### 5.3 以后

| 情况 | 怎么办 |
| --- | --- |
| 加入码过期 | 命令里直接说"加入码已过期，请在 Deneb 里重新生成"。建议有效期从 1 小时延长到 24 小时，用一次就作废 |
| 同一台服务器加了两次 | 认出是同一台（同一份数据、同一个地址），不重复建，提示"这台已经是中转站'东京'了" |
| 升级 | 默认跟着 Deneb 发版自动更新：程序核对签名后自己替换、重启。也能手动 `deneb-relay update` |
| 卸载 | `curl … | sh -s -- uninstall`：停掉服务，删掉程序和数据，通知控制服务器。Deneb 里点"不用这个中转站"，也会让它停止服务 |
| 重启、崩溃 | 服务开机自启、出错自动重启；连续失败就停下，并在 Deneb 里报"中转站反复出错" |
| 资源 | 限 1 核、256 MB，日志最多 30 MB（和现在 Docker 的设置一样） |
| 隐私 | 日志只记必要的，照 PRIVACY.md；程序用无特权用户运行，数据目录只有它能读 |

## 6. 装上以后，确认真的能用

- **控制服务器主动探测**：中转站报到后，以及以后每 10 分钟、地址变了的时候，控制服务器从外面连它：
  - TCP 端口做一次 TLS 握手，核对证书指纹；
  - UDP 端口发一个 STUN 请求。
- **第二个位置**：再从 hk-spare 探测一次，避免只是控制服务器那条线路的问题。由 hk-spare 上的看门狗兼做，做法见 [relay-install-api.md](relay-install-api.md) 第 5 节。
- **设备的实际结果**：主人在线的设备会报告连没连上它，这比服务器探测更接近真实情况，尤其是跨境线路。
- **状态这样算**：

| 状态 | 条件 | 卡片上写 |
| --- | --- | --- |
| 等待安装 | 给了命令，还没报到 | 安装命令，剩余有效时间 |
| 检查中 | 刚报到，正在探测 | 正在检查能否从外网连接 |
| 可以用 | TCP、UDP 都通 | 可以用 |
| 部分可用 | 只有 TCP 通，或只有 IPv6 | 可以用，后面一行说明哪里不通 |
| 连不上 | TCP 不通 | 原因和办法，加"重新检查" |
| 不在线 | 超过 3 分钟没同步 | 最后在线时间 |

- 状态从"可以用"变成"连不上"时，用 alert 告诉主人，不要等他自己发现。
- 状态和原因的 JSON 形状、每种原因的代码和说法，见 [relay-install-api.md](relay-install-api.md) 第 3 节。

## 8. 用户 11-15 定了：都按推荐

1. **默认装法**：引导脚本加单个程序装成系统服务；Docker 留作折叠里的可选项。
2. **没有 root**：支持，改用当前用户的服务，并说明系统防火墙要请管理员放行。
3. **系统防火墙**：问过一句再放行。也可以只打印命令，让用户自己放行。
4. **家里的机器**：自动试 UPnP / NAT-PMP 映射端口。也可以只支持有公网 IP 的服务器。
5. **加入码**：有效期改成 24 小时，用一次就作废。
6. **自动更新**：跟着 Deneb 发版自动更新，核对签名。
7. **架构**：amd64、arm64、armv7 先出；386、riscv64 看需要。

## 9. 引擎线的实现（11-15）

程序在 `cmd/deneb-relay`，引导脚本和发版工具在 `deploy/relay`。中转站和控制服务器之间的接口由控制线定（`proto/relay.go`、`proto/relaystatus.go`）。

### 9.1 一个程序

- 子命令：`install`、`status`、`update`、`uninstall`，服务里跑的是 `run -data <目录>`，另有 `version`。不带子命令时和以前一样只认参数，Docker 里我们自己的几台不受影响。
- 装在哪：

  | | 有 root | 没有 root |
  | --- | --- | --- |
  | 程序 | `/usr/local/lib/deneb-relay/`，目录归中转站自己的用户，它才能自己更新 | `~/.local/lib/deneb-relay/` |
  | 链接 | `/usr/local/bin/deneb-relay` | `~/.local/bin/deneb-relay` |
  | 数据 | `/var/lib/deneb-relay`；OpenWrt 的 `/var` 在内存里，改放 `/etc/deneb-relay` | `~/.local/share/deneb-relay` |

- 数据目录里的 `config.json` 记设置（控制服务器、端口、手动给的地址）和怎么装的（启动方式、路径、用户、放行过的防火墙规则）。`run` 读它；重跑、`status`、`update`、`uninstall` 都靠它。
- 有 root 时新建用户 `deneb-relay`（`useradd`；BusyBox 用 `adduser`；两样都没有的 OpenWrt 用 `nobody`），卸载时删掉。

### 9.2 启动方式

| 机器 | 怎么跑 |
| --- | --- |
| systemd | 系统服务：自己的用户，限 1 核、256 MB、不用 swap，journal 限速，只读系统、只能写自己的两个目录；崩了 5 秒后重启，10 分钟内失败 10 次就停 |
| systemd，没有 root | 当前用户的服务，加 `loginctl enable-linger`，退出登录后也照样运行；开不了 linger 就说明 |
| OpenRC | supervise-daemon 带着跑，5 秒后重启，规则同上 |
| procd（OpenWrt） | 输出进系统日志，重启规则同上 |
| 只有 cron | `@reboot` 一行，每分钟再一行"没在跑才启动"（崩了一分钟内拉起来） |
| 什么都没有（容器） | 直接在后台起，并说明重启后不会自己运行、要加进哪个开机脚本 |
| 没有 root，systemd 在但当前用户用不了它的用户服务（没有登录会话，比如 `su` 过来的），也没有 cron | 同上，说的是"当前用户用不了 systemd 的用户服务"，并提示用 sudo 装成系统服务 |

同一个数据目录只能跑一个中转站：有锁。`status`、cron、重装都靠锁判断它在不在跑。

### 9.3 安装的每一步

1. 系统、CPU，没有 root 的提示。
2. 先找以前装的（`config.json`），再找 Docker 里的旧容器：名叫 `deneb-relay`，或镜像是 `deneb-relay:*`。找到就问一句，迁过来：复制数据目录和参数，把容器停掉、设成不自动重启，容器本身留着，可以退回去。
3. 和控制服务器对时：差 2 分钟以上提醒，10 分钟以上不装。
4. 磁盘：要能放下三份程序（现在的、更新下来的、换下的），再加 40 MB 给数据和日志。
5. 端口：TCP 47445、UDP 47478 被占了，就往上找一组空闲的，并说出是哪个程序占着。手动指定的端口被占了就停下。1024 以下的端口只有 systemd 的系统服务能用（给它 CAP_NET_BIND_SERVICE）。
6. 地址：网卡上的公网 IPv4、IPv6，不要临时 IPv6，默认路由的网卡优先；跳过隧道和容器的网卡。没有公网地址就说明 Deneb 会用它看到的地址，在路由器后面要转发端口。
7. 程序放进去，并试着运行一次（防止这个目录不让运行程序）。SELinux 开着时，把程序目录标成 `bin_t`。
8. 报到：数据目录里已有身份、而且还有效，就不再用加入码（"这台已经是中转站'东京'了"）。Deneb 里删过的，用新的加入码重新报到，证书和钥匙不变。
9. 有 root 时新建中转站自己的用户（9.1）。
10. 系统防火墙（ufw、firewalld、nftables、iptables）：先看两个端口哪个已经放行了，已经放行的不问、不动，卸载时也不收回，那是用户自己的规则；只问、只放行缺的那几个，回车就是同意。没有终端可问时不改，只打印命令。放行过的规则卸载时收回。nftables 和没有持久化工具的 iptables 会提醒"重启后会丢"。
11. 装成服务并启动，等它在本机回应：探测页回答了才算，这时 TCP 和 STUN 都已经在听。起不来就打印最近的日志；开着 SELinux 再提示怎么查。
12. 在路由器后面时，打印端口映射的结果（9.5）。
13. 请控制服务器从外网检查：每个地址打一行（不是公网地址的外网不查，打"没查"，不算失败），再原样打出服务器给的原因和办法。可以用、部分可用时退出码是 0，连不上是 3，没装成是 1。拿到的结果如果是在服务回应以前就查完的（11-15 以前的控制服务器报到时就查，10 秒内再问回上一次的），过了那 10 秒再问一次，免得刚装好就说"连不上"。

没装成时：
- 报到以前出错（加入码不对或用过、端口、程序放不进去）：这一次放进去的程序、链接、数据，迁过来的 Docker 容器，全都还原，说一句"这台上已经改动的都还原了"。
- 报到以后出错（建不了用户、服务起不来）：做过的每一步都随时记在 `config.json` 里。再运行一次同样的命令就接着装，加入码不用重新生成；不装了就运行 `deneb-relay uninstall`，全部清掉。

重跑：同一版本就修复，旧版本就升级，装着的比这个新就留着它。端口沿用原来的。

`uninstall` 没有 `config.json` 时，也认得出没装完留下的东西：程序目录、数据目录、指向它的链接、家目录是数据目录的 `deneb-relay` 用户、写下的服务文件或 cron 行。0.1.8 报到失败时就会留下这些，找到了就说"上次安装没有装完"并全部清掉。引导脚本的 `uninstall` 先取这一版的程序来卸载（旧程序认不出这些），取不到再用装着的。

`status`：先在本机查（服务在不在跑、端口、地址、时间、磁盘），再显示 Deneb 卡片上现在的状态和上次检查的时间（GET `/relay/v1/check`，不重新探测）。`status --recheck` 才当场从外网再查一次。Deneb 里删掉了的（410），或者在别处重新装过的（401），会说明怎么重新用、怎么卸载。

### 9.4 运行中

- 启动：先开始听 TCP 和 UDP，再向控制服务器报到、同步。控制服务器听说它的那一刻（报到、重新上线）就从外网检查，这时已经能连上：检查只做 TLS 握手和 STUN。这一下有设备来连，等它准备好再回答。
- 地址：每分钟看一次网卡，变了下一次同步就报（家里宽带的地址会变）。网卡上的所有地址也一起报（`RelayInfo.Local`），控制服务器靠它认出 1:1 NAT 和路由器后面。
- 同时报怎么装的、防火墙、这一小时重启了几次（`Install`、`Firewall`、`FirewallOpen`、`Restarts`）。
- Deneb 里点了"不用这个中转站"，或者 `uninstall` 通知过（401、410）：停止服务，TCP 和 UDP 两个端口都关掉，原地等着，不退出，免得服务管理程序一遍遍把它拉起来。
- 日志：systemd 进 journal；procd 进系统日志；OpenRC、cron 写自己的 `relay.log`，10 MB 换一个，留两份旧的，共 30 MB。
- 代理：认 `HTTPS_PROXY`，连控制服务器、取更新都走它。连控制服务器时 TLS 和指纹核对是端到端的，代理看不到内容。

### 9.5 家里的机器：端口映射

- 设计稿写的 `tailscale.com/net/portmapper` 只会映射 UDP（给 WireGuard 用），设备连中转站要用 TCP。所以照三个协议各写了最少的几条消息：PCP、NAT-PMP、UPnP IGD，TCP 和 UDP 都映射，没有加新的依赖。
- 什么时候映射：网卡上没有公网 IPv4、没有手动给地址、没有手动设端口转发。在后台进行，云服务器上没有路由器可问，也不会耽误启动。
- 怎么映射：先试 PCP，再试 NAT-PMP（各问路由器一次），最后试 UPnP。外面的端口尽量和里面一样，被占了就往上找几个。只给永久租期的路由器（UPnP 725）就用永久的。
- 维护：租期一小时，过半续一次；停下时收回。
- 结果报给控制服务器（`RelayInfo.PortMap`）。成功时，报的地址和端口换成路由器外面的。路由器自己的外网地址也不是公网地址时，说明是运营商大内网，当不了中转站。

### 9.6 自动更新和发版

- 跟着 Deneb 发版：版本号用 `cmd/deneb/mygo.json` 的。下载站的地址在打包时写进程序，不进仓库。开发版不更新。
- 清单 `relay.json`（最新一版）：

  ```json
  {
    "version": "0.1.9",
    "sha256sums": "<0.1.9/SHA256SUMS 的 SHA-256：安装命令带的就是它>",
    "files": {
      "linux-amd64": {"url": "0.1.9/deneb-relay-linux-amd64", "size": 9876543,
                      "sha256": "<十六进制>", "signature": "<base64>"},
      "linux-arm64": {…},
      "linux-armv7": {…}
    }
  }
  ```

  `url` 相对清单本身。签名照 MyGo 的做法：Ed25519 签文件的 SHA-256，用的是窗口更新的那把钥匙（公钥在 `mygo.json`，程序里也有一份，测试保证两份一致）。
- 取到新版本以后，按顺序核对：大小、SHA-256、签名；再运行一次 `version`，必须是清单说的版本，这样签过名的旧版本改个名字也混不进来。核对都过了，才换上新版本，旧的留成 `.prev`，然后在同一个进程里重启，pid 不变。
- 时机：启动后 10 分钟看第一次，之后每 6 小时看一次，前后错开一成，免得一版发出去所有中转站同时来取。也能手动运行 `deneb-relay update`。
- 下载站 `/download/relay/` 的内容：

  | 文件 | 作用 |
  | --- | --- |
  | `<版本>/deneb-relay-linux-amd64`、`-arm64`、`-armv7` | 程序，静态编译，musl 和 glibc 都能跑 |
  | `<版本>/SHA256SUMS` | 三个程序的校验值 |
  | `relay.json` | 最新一版的清单，最后传 |
  | `latest` | 最新的版本号，给不带校验值的命令用 |
  | `install.sh` | 引导脚本，也就是站点的 `/relay`，下载地址已经写进去 |

- 生成这些用 `deploy/relay/release.sh`（加 `-n` 只看不签）。私钥给 `MYGO_UPDATER_PRIVATE_KEY`；签名和写清单是 `deploy/relay/manifest.go` 做的。

### 9.7 安装命令和引导脚本

- 命令（控制线生成）：`curl -fsSL https://<下载站>/relay | sh -s -- <加入码> <版本>:<SHA256SUMS 的 sha256>`。没有 curl 的把前半换成 `wget -qO-`。
- 脚本先下 SHA256SUMS，核对它的 sha256，再按里面这台 CPU 那一行核对程序，然后运行 `install`。
  - 命令里没有校验值时，读 `latest`，只靠 HTTPS 保证没被改过，并说一声。
  - HTTPS 下载失败、命令里又带着校验值时，退回 HTTP 下载，靠校验值保证没被改过（比如缺根证书的机器）。
- `status`、`update` 交给已经装好的程序。`uninstall` 先下载这一版的程序，用它来卸载，因为它也认得出没装完留下的东西；下载不了或者运行不了，再交给装着的。这台上什么都没有时直接说"这台没有装中转站"，不下载。
- 用的是 POSIX sh，只用 BusyBox 也有的命令。`/tmp` 不让运行程序时，换到 `/var/tmp` 等目录。下载的程序先试着运行一次，再交给它安装。

### 9.8 测过的、没测的

- 单测：
  - 用一台假机器（临时目录当根目录，命令只记下、按真系统的样子回答）配上真控制服务器，把这几种走了一遍：systemd 系统服务（装、重跑、卸载）、没有 root、cron、端口被占、防火墙问答和收回、没有终端时只打印命令、迁 Docker、没有加入码、服务起不来。
  - 还有：各服务文件的内容、crontab 只改自己那两行、认 init、四种防火墙的识别和命令、地址分类、选端口、更新的签名和"旧版改名"、版本比较、docker inspect、日志滚动、锁和重启计数、PCP、NAT-PMP、UPnP（假路由器）。
  - macOS 上和 Linux 上（Alpine 容器里，用 root 运行）都通过。
- Alpine 容器（BusyBox sh、只有 wget、`/tmp` 不让运行程序）：
  - 脚本的 6 种情况都对：带校验值、校验值不对、程序被改过、不带校验值、没装时卸载、多余参数。
  - 真程序对着开发版控制服务器，三种启动方式都装、重跑、看状态、卸载了一遍：什么都没有、cron（杀掉后一分钟内被拉起来）、OpenRC。程序、数据、用户都删干净了。
- systemd 当 1 号进程的容器：装成系统服务后，用的是 `deneb-relay` 用户，内存上限 256 MB、CPU 限额、只读系统、不能提权都生效；`kill -9` 后被拉起来；卸载干净。
- `release.sh -n`（不签名）出的下载目录对；amd64、arm64 的程序能运行。
- 11-15 主会话测出的三处和两个小的，修完在 Ubuntu 26 的 systemd 容器里对着开发版控制服务器复现，先红后绿：
  - 装完马上检查：旧程序对着那时线上的控制服务器（1048cfb），5 次新装 5 次假报"没有程序在听"；新程序对着同一个控制服务器 5 次都是"可以用了"，对着现在的控制服务器也是 5 次都对。
  - 用过的加入码：旧程序留下用户、程序、链接、数据，uninstall 说没装过；新程序什么都不留。旧程序留下的，新程序的 uninstall（经引导脚本）也清掉。
  - ufw 里用户自己的 `allow 47445/tcp`：旧程序卸载时一起删了；新程序只问、只放行 UDP 47478，卸载后用户那条还在。
  - 在 Deneb 里删掉以后：旧程序 UDP 47478 还开着；新程序两个端口都关了。
  - 普通用户、systemd 在但用不了用户服务：说的是"当前用户用不了 systemd 的用户服务"。
  - 单测：开始听在报到以前（报到时 TLS、STUN 已经回答，探测页等它准备好）、删掉后两个端口都空出来、用过的加入码什么都不留、报到以后失败的接着装和卸载、没装完留下的被认出来清掉、四种防火墙已经放行的端口、服务起来以前的检查结果再问一次、没有用户服务时的说法。
- 没测：
  - 虚拟机或真机上的 systemd；当前用户的 systemd 服务（`--user` 加 linger）只在单测里走过；
  - procd、OpenWrt；
  - SELinux；
  - 真路由器的三种端口映射；
  - 真机上的 firewalld、nftables、iptables；
  - armv7 真机（本机的容器只有 arm64）；
  - 用真私钥签的发布和自动更新。

### 9.9 设备报连不上的中转站

设备报到时带上 `relayFailures`（接口见 `relay-install-api.md` §6）：自己各个局域网列表上的中转站，试过、连不上的，每个一条，写明原因和从什么时候开始。连上了就去掉。

| 原因 | 什么情况 |
| --- | --- |
| `connect` | TCP 连不上：没有程序在听、被拒绝、没有路由 |
| `timeout` | 没有回应，路上被挡了 |
| `tls` | 握手失败、钥匙不是记下的那把，或者回应的不是中转站 |
| `refused` | 中转站说不让进，`refused` 带上它说的原因（如 `notListed`）；钥匙对、随后什么也不说就断开的也算 |

- TCP 和 TLS 是设备自己拨号时做的，原因当场记下；之后出的错，derphttp 只留下文字，就按文字分。
- 记下、原因变了、去掉时马上重新报到；内容没变就不发。
- 原本连着、突然断开的（中转站重启、更新），先不报；重连也失败了才报，开始时间从断开时算。
- 换网络、电脑唤醒时全部清空重新判断；列表变了时，"不让进"的清掉重试。
- 只报自己局域网列表上的；为了连某台设备临时连的别处的中转站不报。
- 测过：magicsock 里真的拨号，`connect`、`tls`、`refused` 各一个，连上以后从列表去掉；记账和原因分类的单测；引擎里的中转站测试照旧通过。没测：真网络上的 `timeout`，只在单测里。代码在 `engine/magicsock/conn.go`（`FailedRelays`）和 `engine/control.go`。
