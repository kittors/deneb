# M7 · 注销账号（服务器这一半）

> 控制线，2026-11-12。服务器这一半做好了：`account.delete` 操作和运营方代删的命令，本机测过，没上线。注销按钮、确认页由客户端线出设计，照这份文档来。隐私说明 [PRIVACY.md](../../../PRIVACY.md) §8 说的就是这里。

## 1. 一句话

注销就是：账号删掉，名下的东西一起删掉，只牵扯自己的直接删。牵扯到别人的有两种：

- **局域网**：自己是拥有者，里面还有别人。这种局域网要本人先选：转给别人，还是整个删掉。不选不让注销。
- **中转站**：自己的中转站正被别人用着。不拦，照删，只在确认页提醒。

## 2. 接口

和别的操作一样走 `Op`：设备上走引擎，发到 `POST /device/v1/ops`；网页发到 `POST /api/v1/ops`。只能注销自己的账号，参数里也没有可以指向别人的字段。

```json
{"id": "随便一个不重复的 id", "op": "account.delete",
 "args": {"dryRun": true, "ownedLANs": "transfer", "confirm": "me@example.com"}}
```

| 参数 | 意思 |
| --- | --- |
| `dryRun` | `true`：只说会删什么、什么还挡着，什么都不动，也不用 `confirm`。确认页就靠它。 |
| `ownedLANs` | 自己是拥有者、里面还有别人的局域网怎么办：`transfer` 每个转给最早加入的成员；`delete` 整个删掉，所有人都失去它。不填的话，有这种局域网就拒绝。 |
| `confirm` | 真删时必填：本人的邮箱再输一遍。大小写、前后的空格不算。 |

### 返回

成功时 `result.account` 是 `AccountDeletion`。试算时是"会删的"，真删时是"删了的"，两次的内容一样：

```json
{"version": 412, "result": {"account": {
  "dryRun": true,
  "devices": ["d_…", "d_…"],
  "lans": ["l_…"],
  "transferred": [{"lan": "l_…", "to": "p_…"}],
  "left": ["l_…"],
  "blocked": ["l_…"],
  "relays": ["r_…"],
  "relaysInUse": ["r_…"],
  "shares": 2,
  "invites": 4
}}}
```

| 字段 | 意思 |
| --- | --- |
| `devices` | 这个人的设备，全部删掉，在线的马上登出。 |
| `lans` | 删掉的局域网：只有自己在里面的，或者选了 `delete` 的。 |
| `transferred` | 选了 `transfer`：每个局域网转给了谁。试算时就有，确认页可以写"「工作室」会转给 Mia"。 |
| `left` | 退出的别人的局域网。被邀请、等待同意的也算，那条邀请或申请也一起没了。 |
| `blocked` | 自己是拥有者、里面还有别人，又没选 `ownedLANs` 的局域网。只在试算里出现；不空就没法真删。 |
| `relays` | 自己的中转站（我的服务器、家里的设备），全部删掉。 |
| `relaysInUse` | 其中正被别人用着的：拖进了有别人的局域网，或者是部署的默认中转站。那些设备会改走公共中转站。 |
| `shares` | 给出和收到的分享，几次。 |
| `invites` | 发出的、发给自己的、自己用过的邀请，几个。 |

列表都按 id 排好，空的给 `[]`。`transferred`、`blocked`、`relaysInUse` 没有内容时不出现。界面要显示名字，就到自己的视图里按 id 找：这些东西注销前都在本人的视图里。

### 拒绝

| 情况 | 状态码 | `code` | 给人看的话（`message`，原样显示） |
| --- | --- | --- | --- |
| 部署的种子文件里写着的账号（§4.3），试算也一样 | 403 | `forbidden` | 这个账号写在部署的种子文件里，服务器每次启动都会把它建回来：要注销，先请部署管理员把它从种子文件里拿掉 |
| `ownedLANs` 不是两个值之一 | 400 | `invalid` | ownedLANs 只能是 transfer 或 delete |
| 有挡着的局域网，没选 `ownedLANs` | 409 | `conflict` | 你是「工作室」、「家」的拥有者，里面还有别人：先选好转给别人还是整个删掉，再注销 |
| `confirm` 不是本人的邮箱 | 400 | `invalid` | 要注销，请再输一遍你的邮箱 |

### 删完以后

- **本人的设备**：和 `device.delete` 一样。设备流最后一帧是 `loggedOut`，再调接口得到 `not_logged_in`。发起注销的那台也一样：它先收到成功的回答，然后被登出。在这台机器上再登录，就是一台新设备、一个新地址。
- **浏览器**：会话全删。网页的流最后一帧是 `loggedOut`，随即断开；再调接口得到 `unauthorized`。
- **重试**：同一个 op id 十分钟内重发，拿到的是第一次的回答，不会报错。
- **别人**：视图里不再有这个人。成员列表、分享、设备、中转站的卡片里都没有了。转来的局域网，拥有者那一栏换成了接手的人。

## 3. 删什么，留什么

**删掉**

- 账号：邮箱、名字、显示名、头像字，还有运营方给的单独座位数和管理员身份。
- 设备：每一台，连同报上来的地址、服务目录和打开的服务、拒绝名单、在各局域网里的位置。设备的虚拟地址冷却 30 天再给别人。
- 局域网：只有自己在里面的删掉；里面有别人的，按 `ownedLANs` 转让或删掉；别人的局域网，退出。
- 分享：给出的和收到的，连同为它打开的服务。
- 邀请：发出的、发给自己的、自己用过的（"谁接受了"这条记录也算）。
- 拒绝：别人设备上拒绝自己的那几条（自己设备上的随设备删掉）。
- 自己的中转站：连同各局域网里的位置、记下的流量、登记码、在上面踢人的记录；还没用掉的登记码也删。
- 踢人：踢自己的、踢自己设备的。
- 浏览器会话。

**留下**

- **经别人中转站的流量**：留在那台中转站的月度合计里，和 `device.delete` 一样。设备已经删了，这几行只剩一个对不上任何人的设备 id。按清理规则，三个月后删掉。
- **自己当部署管理员时，在公共中转站上踢的人**：继续有效，改记成"部署管理员"踢的。注销不该顺带放回被踢的人。
- **日志**：注销以前的日志里有这个人的邮箱和地址（登录、验证码），最多再留 30 天。注销这一行只记账号 id 和遮盖过的邮箱：账号没了，邮箱就按"没账号的邮箱"遮盖，只留域名和一个短哈希。
- **备份**：数据库每天的备份留两个月左右（7 天每天一份，再往前每周一份，留 8 周），部署时的数据副本留两个月。这段时间里备份里还有这个人；到期自然删掉，不单独去改备份。

## 4. 两种难办的情况，以及建议

### 4.1 自己是拥有者，里面还有别人

**建议：默认拦住，让本人选，界面推荐"转给最早加入的成员"。**

- 默认拦住：删掉局域网，会把里面所有人的连接一起断掉，服务器不该替本人决定。
- 推荐转让：别人什么都不用做，局域网照常；接手的人想删，可以自己删。
- 最早加入的成员：按加入时间算，只算已经加入的人，被邀请、等待同意的不算。同一时刻加入的，按账号 id 排，结果每次都一样。
- 只有被邀请、等待同意的人：不算"里面有别人"，直接删掉，那些邀请和申请一起没了。
- 转让以后：
  - 接手的人成了拥有者，什么都能管：改名、删除、邀请、同意新成员和新设备、拖中转站。
  - 局域网的设置（新设备要同意、新成员要同意、用法）照旧。还在等同意的人和设备，由接手的人来同意。
  - 原拥有者的设备随账号删掉，设成公共设备的也一样，因为是用他的账号登录的。接手的人要接着用那台机器，就在上面换自己的账号登录，再设成公共设备。
  - 原拥有者拖进来的中转站随账号删掉，局域网改走别的中转站（§4.2）。
- 整个删掉：里面所有人都失去这个局域网，设备从里面出来，邀请链接失效。里面的公共设备，他自己登录的随账号删掉，别人登录的回到登录它的人名下（和 `lan.delete` 一样）。
- 一次只能选一种：要么全转，要么全删。要一个转、一个删，就先用 `lan.delete` 删掉不要的那个，再注销选 `transfer`。

### 4.2 自己的中转站正被别人用着

**建议：不拦，照删，确认页提醒。**

- 中转站跑在这个人自己的机器上，账号没了，它不该再替别人转发。
- 别人的设备会自动改走别的中转站：局域网自己列表里的下一个，没有就用部署的默认中转站和公共中转站。经它中转的连接会断一下，引擎拿到新的网络图就换过去，可能比原来慢。
- 试算返回 `relaysInUse`，确认页据此提醒：「你的『香港』中转站正被别人用着，注销后他们会改走公共中转站，可能慢一些」。
- 中转站那台机器上的容器，服务器管不着。服务器这边删掉以后，它再连上来会被拒绝，设备也不会再用它，但容器还在跑。注销完成页提醒本人自己去停：
  `docker rm -f deneb-relay && docker volume rm deneb-relay`

### 4.3 种子文件里的账号

- **拒绝（403），试算也一样**。服务器每次启动，都按部署的种子文件把里面的账号建回来，注销了也会回来，只是变成一个空账号。种子文件里写着的中转站，它的拥有者也算在内。
- 要注销这种账号：部署管理员先从种子文件里拿掉，重启，再注销。
- 种子文件里放的是测试账号（`SeedAccount` 本来就是为测试设的）。普通人登录时建的账号不在种子文件里，不受这一条影响。

## 5. 界面建议（给客户端线）

1. **入口**：设置 → 账号 → 「注销账号」，放在最下面，红字。网页版和桌面一样。
2. **点开先试算**：发 `dryRun: true`，不带 `ownedLANs`，按返回的内容说会删什么。
   - 「N 台设备会登出并删掉」，列名字；
   - 「这些局域网会删掉」「会退出这些局域网」，列名字；
   - 「N 次分享、N 个邀请会删掉」；
   - 「N 个中转站会删掉」，列名字。
3. **`blocked` 不空**：列出这些局域网，给两个选项。
   - 「转给最早加入的成员」（推荐，默认选中）：选了就再发一次 `dryRun: true, ownedLANs: "transfer"`，用 `transferred` 写出「『工作室』会转给 Mia」。
   - 「整个删掉，里面的人都会失去它」。
4. **`relaysInUse` 不空**：照 §4.2 提醒。
5. **确认**：输入框，让人再输一遍自己的邮箱，旁边写「注销后不能恢复」。按钮「注销」，邮箱对上才能点。
6. **真删**：发 `confirm` 加上选好的 `ownedLANs`。成功后客户端会收到 `loggedOut`，回到登录页，显示「账号已经注销」。有自己的中转站的，提醒去机器上停容器（§4.2）。
7. **不给撤销**：别的操作那种 4 秒撤销不适用，确认页就是最后一道。
8. **403（种子账号）**：试算就会遇到，把 `message` 原样显示，不显示后面的步骤。

## 6. 运营方代删

有人发邮件要求注销、自己又点不了按钮时，运营方在服务器上跑：

```
deneb-control account-delete -email <邮箱>                    # 只试算，说会删什么、什么挡着
deneb-control account-delete -email <邮箱> -lans transfer -yes  # 真删；有挡着的局域网时要选 -lans
```

不带 `-yes` 只试算。走的是同一个 `account.delete`，规则完全一样，种子账号同样拒绝。日志多记一行 `admin: account p_… deleted by the operator`。

## 7. 测试

`TestAccountDelete`（control/account_test.go）：

- 种子账号被拒，试算也一样。
- 试算什么都不改，说得和真删一样：设备、自己独有的局域网、挡着的局域网、退出的局域网、中转站和其中在用的、分享、邀请；转让时转给最早加入的人。
- 挡着时拒绝，`ownedLANs` 不认识时拒绝，邮箱不对时拒绝，三种都什么都不改。
- 真删：
  - 设备的流以 `loggedOut` 结束，再调接口得到 `not_logged_in`；浏览器会话没了；
  - 局域网转给了先加入的 Mia，她能管；自己独有的局域网没了；
  - 分享和为它打开的服务、拒绝、邀请、登记码、中转站和它的用量、踢自己的记录都没了；
  - 自己在公共中转站上踢的人照样被踢，记成部署管理员；
  - 别人的视图里找不到这个人的 id、邮箱、设备和中转站；
  - `PRAGMA foreign_key_check` 干净。
- 运营方代删：默认只试算；挡着时拒绝；选 `delete` 后局域网对里面的人也没了；删第二次报"没有这个账号"。

`TestNoOneActsOnOthers` 把 `account.delete` 记为"只动自己的"操作。

## 8. 还没做的

- **界面**：客户端线照 §5 出设计。
- **告诉别人**：局域网转给了谁、局域网被删、中转站没了，现在别人只能从卡片上看出变化，没有一条消息说明原因。要做的话，服务器得加一种事件，客户端加提示，比如「Mia：kittors 注销了账号，『工作室』转给了你」。等界面设计时一起定。
- **单独的"转让局域网"**：现在只有注销时能转。要不要做成平时也能用的操作，等界面设计时定。
- **同一个邮箱再来**：开放注册打开时，会建一个新的空账号；关着时登录不了，和从没注册过一样。线上的部署脚本没开 `-open-signup`，是关着的。
- **上线**：没上线。上线后第一次注销前，先在线上跑一次 `deneb-control account-delete -email <测试账号>` 试算看看。
