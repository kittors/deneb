# 第9批：对齐和间距的检查清单

> 用户 11-16："这个没有垂直居中，所有的页面如果存在类似的布局的问题都得修复下。"
> 又说："存在很多对齐的问题，包括间距等等问题，这些基本的布局问题，你得给我仔细检查好。"

这份清单记下：每一页查了哪些状态，找到了什么问题，每个问题在哪个组件里修、怎么修。规矩写在 DESIGN §3.9，这里只记这一次的检查结果。

## 1. 查什么

1. **一行里的东西在一条中线上**：同一行里的字、图标、按钮、头像、开关，各自看得见的部分的中线相差不超过 0.5pt。字按字本身算，不算它的内边距。
2. **一列里的东西从一条边起头**：
   - 一列里从左边起头（离边 16 以内）的东西，左边缘相差不超过 0.5pt。
   - 行尾是记号（×、↗、›、开关、按钮）的，右边缘也一样。
3. **间距只用 4 的倍数**：
   - 内边距、外边距、子元素之间的间距都算。
   - 按"同一组里 < 组与组之间 < 区块之间"分配。
   - 卡片、对话框、灰底的框，四周内边距相等。
4. **修在组件里**：同一种东西只有一个组件，不给单个元素加偏移。

## 2. 怎么查

- **检查器**：`cmd/deneb/rowalign_test.go`。
  - 读 MyGo 排好的版面：每个元素的位置、内边距、外边距、间距、圆角，以及它看不看得见。
  - 只读不改，按 MyGo v0.7.4 的内部结构写。换了版本，测试会跳过并提示，要对着新版本的内部核对一遍。
- **窗口大小**：980×640（最小）、1180×740（平常）、1440×900（大）。
- **状态**：34 个，按页列在 §4。每个状态从演示数据开始，用点击、键盘和演示事件走到那一步（局域网卡片除外：直接打开，和点页头的名字一样）。
- **测试**：
  - `TestLayoutRules`：34 个状态 × 3 种窗口，查 §1 的三条。
  - `TestPanelLayoutRules`：菜单栏小窗，带上待处理的事。
  - `TestHeaderLinesMeet`：页头两行的中线。
- **报告**：`DENEB_LAYOUT_AUDIT=文件 go test -p 1 -run TestLayoutRules ./cmd/deneb` 把所有发现（包括例外）写进一个文件。本页的数字都出自它。
- **截图**：`DENEB_ALIGN=文件夹 go test -p 1 -run TestAlignShots ./cmd/deneb`。
  - 每个状态截浅色、深色两种主题，窗口取窄、中、宽三种，都是两倍清晰度。
  - 修之前和修之后成对放在桌面"M7-公测/第9批-对齐和间距"。
- **检查器自己的例外**：下面这些不是毛病，检查器本来就不当毛病报。
  - 自己定位的东西（AlignSelf）。
  - 浮在上面的东西：提示条、弹出卡片、拖动中的设备。
  - 居中排或靠右排的一列。
  - 画布上自由摆放的设备。
  - 换行的标签：一行一行分开查。
  - 底色占满装着它的那一格时（侧栏里选中的那行、新建局域网的输入行、菜单栏小窗"要你处理"的灰底、设置开着时亮着的齿轮按钮）：它自己的边或里面东西的边，有一个和别的对齐就算齐。
  - 转着的东西（转圈）：按它不转时的大小算，不按转过的方框算。
  - 关闭（×）和外链（↗）两个图标按笔画量：笔画离 16 的框各有 4，行尾的它们按笔画对齐（见 §4.7）。
  - 指针先移出窗口再查：悬停的底色是光，不是版面。
  - 只设左右内边距的面板，是靠高度让里面居中的一行（列表的行、按钮），不要求四周相等，由中线那条去查。
