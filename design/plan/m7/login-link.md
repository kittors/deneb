> 控制线，2026-11-13。用户 11-13 看过客户端线交的第 2 批设计（DESIGN §14.14，桌面 `Deneb组网demo/M7-公测/第2批-登录和空状态/`），四件都按推荐定了，原话"都可以"。归控制线的三件做好了，本机测过，没上线。客户端线照这份接网页。

## 0. 一句话

- **验证码邮件**：一封信里有 HTML 和纯文本两份，小星图标随信附带。标题是"Deneb 验证码 <码>"。网页登录的信里多一个按钮"在这台电脑上登录"。
- **点链接登录**：
  - 链接是 `https://<网页>/login/link#<令牌>`。打开只到网页上的确认页，点了才登录。
  - 链接和验证码一样，10 分钟有效、只能用一次；用了其中一样，另一样作废。
  - 在原来那个浏览器里点开：原来的登录页自己进去，靠的是浏览器里的 BroadcastChannel，外加页面重新可见时查一次（§5）。
- **网页新建局域网**：要用的 `lan.create`、`lan.rename` 都已经有了，网页里也测过，不用补。

## 1. 验证码邮件

- **标题**：`Deneb 验证码 <码>`。手机通知、收件箱列表里一眼就看到。
- **结构**：`multipart/alternative`。
  - 先是纯文本；
  - 再是 `multipart/related`：HTML，加上图标。图标是 `image/png`，`Content-ID: <deneb-icon@deneb.mail>`，HTML 里写 `cid:deneb-icon@deneb.mail`。
  - 每一部分都是 base64，行宽 76，全是 ASCII。
- **样子**：照客户端线的 `08-验证码邮件/` 模板，表格排版，样式写在标签上。模板放进了 `control/mailtmpl/code.html` 和 `code.txt`。
  - 图标是 `design/brand/final/macos/AppIcon.iconset/icon_32x32@2x.png`（64 像素，显示成 32），拷成了 `control/mailtmpl/icon.png`，测试会核对它和品牌目录里的那个一模一样。
  - 邮箱挡住图片时，显示"✦"，旁边照样是"Deneb"。
- **按钮**：只有网页登录、而且服务器设了 `-web-url` 时才有。
  - 正文那句改成："10 分钟内有效，只能用一次。回到 Deneb 的登录页填进去，或者点下面的按钮直接登录。"
  - 下面一个蓝色按钮"在这台电脑上登录"，品牌蓝 `#2f6bff`，表格做的按钮，各家邮箱都按得了。
  - 纯文本版多一段："也可以打开下面的链接，在这台电脑上直接登录。链接也是 10 分钟内有效，验证码和链接用了一样，另一样就作废：" 后面跟链接。
- **设备的登录**（桌面客户端第一次登录、命令行登录）：信里没有按钮。链接登录的是浏览器，不是那台设备。
- **信的最下面**：
  - 设了 `-web-url`，写网页的地址；
  - 隐私说明的链接，指向 GitHub 上的 PRIVACY.md。
- **想在浏览器里看信的样子**：
  ```
  DENEB_MAIL_PREVIEW=<目录> go test -p 1 ./control -run TestCodeMail
  ```
  会写出 `code-browser.html`（带按钮）、`code-device.html`（不带）和对应的 `.txt`。图标换成了内嵌的，因为浏览器不认 `cid:`。

## 2. 链接

- **样子**：`https://<网页>/login/link#<令牌>`。
  - 令牌 43 个字符，字符是 `A-Z a-z 0-9 - _`。
  - 在 `#` 后面，浏览器从来不把它发给服务器。所以打开链接、邮件扫描器预先打开，服务器都不知道，也什么都不用掉。
- **有效期和用法**：
  - 跟这次的验证码一样，10 分钟；
  - 只能用一次；用了验证码，链接作废；用了链接，验证码作废；
  - 每封信（包括重发的）一条新链接。同一个码的几条都能用，用掉一条全部作废；
  - 码过了一半有效期再要，换新码，旧码的链接一起作废；
  - 同一个码错 5 次作废，链接也跟着作废。
- **服务器那边**：只存令牌的 SHA-256，在内存里，和验证码一样，重启以后要重新要。日志不记令牌。

## 3. 接口

两个都是 `POST`、JSON（`Content-Type: application/json`），和别的登录接口一样有同源检查。令牌放在请求体里，不放在网址里。

### `POST /api/v1/login/link/info`：看链接是谁的，什么都不用掉

请求：

```json
{"token": "<# 后面那一串>"}
```

返回：

| 情况 | 状态 | 内容 |
| --- | --- | --- |
| 能用 | 200 | `{"account": "lin@example.net", "expiresAt": "2026-11-13T08:10:00Z"}`：要登录的邮箱，链接到什么时候失效 |
| 用过、过期、被新码顶掉、根本没有 | 404 | `{"error": {"code": "not_found", "message": "这个登录链接用不了了：已经用过、过期了，或者后来又发了新的验证码。回到登录页再发一封就行。"}}` |
| 同一个地址试了太多无效的链接或者错码（15 分钟 30 次） | 429 | `{"error": {"code": "forbidden", "message": "试错的次数太多了，请 15 分钟后再试"}}` |

### `POST /api/v1/login/link`：登录，用掉链接和验证码

请求同上。返回：

| 情况 | 状态 | 内容 |
| --- | --- | --- |
| 登录了 | 200 | 和输对验证码一样：`{"step": "done", "account": "lin@example.net", "person": "p_…"}`，带 `Set-Cookie: deneb_session=…`（HttpOnly、SameSite=Lax，HTTPS 下 Secure，30 天） |
| 用不了 | 404 | 同上那句 |
| 太多次 | 429 | 同上 |

`message` 原样显示就行。登录以后和用验证码登录完全一样：`/api/v1/userview` 能拿到视图，`/api/v1/stream` 能连推送流。

## 4. 网页要做的（客户端线）

1. **新的页面 `/login/link`**：
   - 一进来读 `location.hash`（去掉 `#`），马上用 `history.replaceState` 把令牌从地址栏去掉，免得留在浏览历史、截图里。
   - 调 `/api/v1/login/link/info`：
     - **200**：显示要登录的邮箱和按钮，措辞分两种（怎么分见第 3 条）：
       - 在原来那个浏览器里：比如"登录 Deneb"，加一句"原来的页面也会自己进去"；
       - 在别的浏览器、手机里："在这里登录 Deneb？"。

       两种都要点一下才登录。
     - **404**：把 `message` 显示出来，给一个"回到登录页"。
   - 点了，调 `/api/v1/login/link`：
     - 200 以后，在 `BroadcastChannel("deneb-login")` 上发 `{type: "logged-in"}`，再进网页，和验证码登录成功一样。
     - 404，显示 `message`。
2. **原来的登录页**（第二步，等验证码的时候）：
   - 听 `BroadcastChannel("deneb-login")`：
     - 收到 `{type: "logged-in"}`，就 `GET /api/v1/userview`，200 就进去，和输对验证码一样；
     - 收到 `{type: "who-waits"}`，就回 `{type: "waiting", account: <这一页的邮箱>}`。
   - 页面重新可见（`visibilitychange`）或者拿到焦点时，也 `GET /api/v1/userview` 一次，200 就进去。这一条兜着收不到消息的情况：浏览器把后台的标签页冻住了，或者老浏览器没有 BroadcastChannel。
3. **链接页怎么知道自己在不在原来那个浏览器里**：
   - 打开时在 `deneb-login` 上发一次 `{type: "who-waits"}`，等 150 毫秒左右。
   - 有回答、`account` 和链接的邮箱一样，就是原来那个浏览器；没有回答，就当是别处。
   - 猜错了也没事：两种都要点一下，只是说法不同。
4. **登录完要去的地方**：和验证码登录一样，照 §14.14 的规矩，永远不会是登录页、邀请页或者别的网站。

## 5. 为什么让原来的页面自己在浏览器里知道，不让服务器通知

要的是：在原来那个浏览器里点了链接，原来的登录页自己进去；在别处点，原来的页面照旧等验证码。

- **会话本来就是浏览器的**：链接页登录时，服务器把会话 cookie 发给了这个浏览器，同一个浏览器的每个标签页都带着它。原来的页面其实已经登录了，缺的只是有人告诉它一声。
- **BroadcastChannel 正好只到同一个浏览器**：同一个网址、同一个浏览器里的标签页都收得到；别的浏览器、手机收不到，原来的页面也就照旧等验证码。这正是要的区分，不用服务器去认"是不是同一个浏览器"。
- **服务器不用多存东西**：要让服务器通知，就得在要码时给浏览器再发一个记号，记下"谁在等"，再让原来的页面挂一条长连接等着。多了状态、多了接口，也多了能被拿来试探的东西。
- **兜底**：页面重新可见或拿到焦点时查一次 `/api/v1/userview`，覆盖被冻住的标签页和没有 BroadcastChannel 的老浏览器。人从邮件切回原来的页面，正好会触发这一下。

## 6. 本机怎么试

- 起本机的开发服务器，带上网页的地址，信里才会有链接。`-web-url` 写 deneb-web 实际听的地址，主会话那台是 47621：
  ```
  go run ./cmd/deneb-control -dev -web-url http://127.0.0.1:47621
  ```
  再起 deneb-web，连这个服务器（`-control http://127.0.0.1:47080`）。
- 开发版不真发信（`-mail log`）：验证码和链接都写进服务器的日志：
  ```
  mail (development, not sent): its login link is http://127.0.0.1:47621/login/link#…
  ```
  只有开发版这样；线上发真信，日志里没有码，也没有链接。
- 种子里的测试账号（`@deneb.test` 这些）不发信，用固定码，所以也没有链接。要试链接，开 `-open-signup` 用一个别的邮箱，或者在种子里加一个不带码的账号。

## 7. 网页新建局域网

- **建**：`lan.create`，参数 `{name}`，经 `/api/v1/ops`。
  - 在网页里建，局域网是空的：浏览器不是设备。电脑装好以后拖进来。
  - 返回 `result.lan`，是新局域网的 id。
- **改名**：`lan.rename`，参数 `{lan, name}`，只有拥有者能改。
- 两个都已经有了，网页里也测过（`TestWebAPI`）。服务器不用补。
- **默认的名字**由网页起，和桌面一样（`cmd/deneb/onboard.go`）：
  - 显示名加"的局域网"，名字是拉丁字母的，前后加空格，比如"tom 的局域网"；没有名字就叫"我的局域网"。
  - 自己已经有同名的局域网，服务器回 409："你已经在一个叫「…」的局域网里了"。网页按视图里已有的名字换一个，比如"tom 的局域网 2"。
- 名字的规矩和桌面一样，由服务器检查：去掉首尾空格，不能是空的，最多 40 个字，不能有控制字符。不合格回 400，原样显示 `message`。

## 9. 没做的

- **没往真的邮箱里发过**。接线以后，先问过用户，发一封到用户自己的邮箱，看各家邮箱里的样子。
- **设备登录链接**（`/login?c=…`）还在控制服务器自己的页面上，和这次的链接登录无关。
- **上线**：没上线。上线以后，信里要有按钮，控制服务器得带着 `-web-url` 起。部署脚本在 `WEB_LIVE=yes` 时会带上（[web-deploy.md](web-deploy.md)）。
