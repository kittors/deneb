# 查外网地址的服务（STUN）

> 状态：引擎线 11-18 写。§1–§3 是服务器和引擎那一半，已经做了，照主会话 11-18 转达的用户决定：用 Cloudflare 免费的 STUN，由控制服务器下发，可以配置。§4 是网页运营后台那一块的方案，**等用户看过、点头再做**。

## 0. 为什么

- 两台设备要直接连上，各自得知道自己在外网的地址和端口，再告诉对方。原来只问中转站（中转站自带 STUN）。
- 11-16 起，国内家里的线路到 hk-155 的地址被挡，中转站的 STUN 没有回答。设备不知道自己的外网地址，对方没处打洞，两边只能一直经中转。
- 现在设备还会问网络图里列出的"查外网地址的服务"，默认是 Cloudflare 的 `stun.cloudflare.com:3478`。哪个回答了就用哪个。

## 1. 网络图

- `NetMap.STUN`：一项一个服务，有主机名、端口，和控制服务器查到的 IPv4、IPv6（`proto.STUNServer`）。只发查到地址的。
- 功能开关 `stun`（`proto.FeatureSTUN`）：服务器能列、加、删这些服务；网页那一块只在有这个开关时出现。
- 老版本的引擎不认识这一项，照旧只问中转站。

## 2. 控制服务器

- 列表存在数据库里（迁移 15，`stun_servers`），一开始只有 Cloudflare 的那一个。
- 名字在控制服务器上查（香港），设备不在本地查：本地的 DNS 可能是代理软件的假地址。
  - 启动时查一次，之后每 10 分钟查一次，加一个时马上查。
  - 查到的地址里还有原来那个，就不换，免得名字每次换个顺序，所有设备都收到一份新的网络图。原来的没有了，换成新的里最小的那个。
  - 没查到：保留上次的地址，日志里写一句。
- 管理命令 `deneb-control stun`：
  - 不带参数：列出每一个的地址、什么时候查的、查到没有；
  - `-add 主机名[:端口]`：先查地址，查不到就不加；不写端口是 3478；最多 8 个；
  - `-remove 主机名[:端口]`：去掉。可以全去掉，设备就只问中转站。
- 加和去掉都记进运营记录（"加了查外网地址的服务 stun.example.com:3478"），也写进服务器日志。地址自己变了只写日志。

## 3. 引擎（0.1.11）

- 除了连着的中转站，每 20 秒也向网络图里的每个服务发一个标准的 STUN 请求（RFC 5389 Binding）；刚启动、换了网络、网络图换了列表时马上问。
- 用下发的 IPv4，不在本地查名字；走和现在一样的 UDP 端口，绑在物理网卡（en0）上，不经代理。
- 哪个回答了就用哪个；回答不一样（每个服务看到不同端口的路由器）就都告诉对方。中转站的 STUN 不通也照样能打洞。
- 日志写清是谁看到的：`[stun] public address as stun.cloudflare.com:3478 at <地址>:3478 sees it: <外网地址>`。
- `deneb status` 多一行"外网地址：…（stun.cloudflare.com 看到的）"。
- 网络图里去掉的服务，它看到的地址马上不用；换了网络，全部重新问，旧网络上迟到的回答不算。
- 隐私：服务看到设备的 IP 和端口，别的都没有（PRIVACY.md §6）。

## 4. 网页运营后台：公共中转站页上的一块（用户 11-18 定了，都按推荐）

做在分支 `claude/stun-console` 上。录屏和截图在桌面"M7-公测/第18批-查外网地址的服务"，用的是网页自带的演示服务器跑的真页面；原型那一版挪进了"旧版本/M7-第18批-查外网地址的服务-原型"。

### 4.1 放在哪

- 公共中转站页，中转站那口井下面再放一口同样的井（中间空 16，和概况那几张卡片一样），标题"查外网地址的服务"，右上角是个数，比如"1 个"；一个都没有时不写数。
- 服务器没有 `stun` 开关时不出现。
- 这是做什么的，放在标题的 tooltip 里："设备向这些服务问自己在外网的地址，好和别的设备直接连上。它们只看得到设备的 IP 和端口。"
- 两口井加起来比窗口高时，这一页能往下滚，最下面留 24；提示条和卡片不跟着滚。窄窗口里两口井照现在的样子上下排。

### 4.2 一行一个

- 每行前面一个点，左边和标题对齐；然后是名字（端口是 3478 时不写），下面一行小灰字：
  - 绿点：上次查到了。"198.51.100.10 · 6 分钟前查过"，每分钟跟着变。
  - 黄点：上次没查到，设备先用上次的地址。"没查到地址，先用上次的 198.51.100.30"。
  - 灰点：一直没查到地址，设备先不问它。"还没查到地址，设备先不问它"。
- 悬停名字：tooltip 里是完整的名字和端口、IPv4、IPv6、上次没查到时查的结果、哪天加的。名字太长时省略，悬停看全。
- 悬停这一行（或者键盘移到它上面），行尾淡出文字按钮"去掉"；触屏上一直显示。字和标题右边的个数对齐，底色向外伸。

### 4.3 加一个

- 最后一行"＋ 加一个"，整行是按钮：悬停有底色，按下底色深一档。
- 点了，"加一个"先淡出，原地再淡进输入框（占位"stun.example.com"）、主要按钮"加"和文字按钮"取消"；这一行的高度不变。Esc 或"取消"收回，收回时也是一次一件事。
- 点"加"或回车：0.2 秒后"加"的字换成转圈（按钮大小不变，出了至少转 0.4 秒），服务器先在香港查这个名字。
  - 查到了：新的一行在最后长出来（下面的先让开，快到位了它再淡进来），输入框随后收回成"加一个"。
  - 没加上：转圈换回"加"，输入框的边变红，下面淡进一行红字，是服务器说的原话："查不到 stun.nowhere.example 的地址，没有加""写成主机名，或者主机名:端口，比如 stun.cloudflare.com:3478""已经有 stun.example.com:3478 了"。输入框留着、字选中，好改；一打字红字就淡出。
- 满 8 个："＋ 加一个"变灰，tooltip"最多 8 个，先去掉一个"。

### 4.4 去掉

- 还剩别的：点"去掉"，这一行先淡出，下面的再合上来；提示条"去掉了 stun.example.net:19302 · 撤销"。和别处能撤销的一样，提示条走了才真告诉服务器，撤销就是这一行回到原位。
- 最后一个要再点一下：第一下，"去掉"换成红字"再点一下，去掉"，名字下面那行换成红字"去掉以后，设备只问中转站"；3 秒内再点才去掉，不点就换回原样。去掉以后照样有撤销。
- 一个都没有：井里一句"没有查外网地址的服务，设备只问中转站"，下面是"＋ 加一个"。
- 加和去掉都记进运营记录。

### 4.5 出错、别人同时改

- 连不上服务器（页头那句会说）：加的时候，输入框下面红字"没能加上，再试一次"；去掉的时候，提示条走了才发现没去掉，那一行回到原位，提示条"没能做成，再试一次"。
- 别的管理员同时改了：以服务器的为准，跟着视图刷新；正在淡出的行先淡完，不会一下没了。

### 4.6 用户定了（11-18，都按推荐）

1. 放在公共中转站页，中转站那一块下面。
2. 去掉一律给"撤销"；去掉最后一个要再点一下。
3. 名字下面那行写一个地址（有 IPv4 写 IPv4）和多久以前查过，IPv6 放进悬停。

### 4.7 服务器那一半

- **列表和状态**：部署管理员的视图里有 `Operator.STUN`，每一项是名字和端口、IPv4、IPv6、哪天加的、上次查的时间和结果（`proto.OperatorSTUN`）。查的结果在服务器的内存里（`stunLooks`），照中转站检查结果的样子接进 World（`stunLook`），出视图时读。别人的视图里没有。
- **多久以前查过跟着走**：每 10 分钟查完一轮都发一个版本，地址变了就和 UPDATE 一起发。帧去掉版本号以后一样的不发（`hub.deliver`），所以只有管理员的视图收到新的查的时间，设备什么都收不到；地址变了，设备才收到新的网络图。
- **加和去掉**：网页走现成的 op 通道，`stun.add`、`stun.remove`，只有部署管理员能做，别人的回 403。加的时候先在服务器的锁外查名字（`prepareOp`，查名字可能要几秒），再进事务；不是管理员的不替他查；同一个 op id 重试拿到第一次的回答，不再查一遍。命令行（`deneb-control stun`）和网页用同一套加、去掉的步骤。
- **说清楚出了什么事**：查不到只说"查不到 X 的地址，没有加"，英文原因写进日志；写得不对、已经有了、满了，照原来的话。
- **撤销**：网页照别处能撤销的做法，提示条走了才发 `stun.remove`，撤销就是不发，服务器不用另做撤销。
- **运营记录**：加和去掉各记一行，是谁做的写那位管理员（命令行写"服务器上的命令"）；被拒绝的不记。
- 红色没有 token，用的是概况页那个红；要不要进调色板，跟着客户端线的 token 一起定。
